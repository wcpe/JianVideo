# ADR-0004：mpegts.js 作为 Web 播放内核

## 状态
已接受

## 背景
前端需要播放 MPEG-TS 流。候选方案包括 mpegts.js、xgplayer（TS 插件）、hls.js、原生 video 标签。需要权衡 TS 流支持、MSE 缓冲区控制、追播能力和社区活跃度。

## 决策
前端强制使用 mpegts.js 作为播放内核，通过 MSE API 手动控制缓冲区。

## 理由
- **TS 流原生支持**：mpegts.js 专为 MPEG2-TS 实时流设计，可直接解析 TS 数据包并送入 MSE。
- **实时追加能力**：支持将新到达的 TS 数据追加到 SourceBuffer，实现"边下边播"和实时追播。
- **追播控制**：内置缓冲区管理逻辑，可配置追播延迟（3-5 秒），在文件持续写入时自动追随。
- **Seek 支持**：通过 HTTP Range 请求实现精准 Seek，配合后端固定 GOP 实现毫秒级响应。
- **社区活跃**：开源项目持续维护，Issue 响应及时。

## 后果
- 前端播放器代码需要手动管理 MSE 缓冲区，比原生 video 标签复杂。
- 不能直接使用原生 video 控件的所有功能（需自定义播放控制 UI）。
- 内存管理需要关注，长时间播放可能积累大量缓冲区数据。

## 备选方案
- **xgplayer + TS 插件**：功能更全面但体积大，依赖 xgplayer 框架，灵活性不如直接使用 mpegts.js。
- **hls.js**：仅支持 HLS 格式（m3u8），无法直接处理裸 TS 流，追播能力有限。
- **原生 video 标签**：无法播放 TS 流，仅适用于 HLS 在 Safari 的原生播放。
