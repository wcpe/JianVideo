# ADR-0001：Go 作为后端语言

## 状态
已接受

## 背景
项目需要一款跨平台、可编译为单文件的视频媒体服务器。候选语言包括 Go、Rust、Python、Node.js。需要权衡部署便捷性、并发性能、生态成熟度和开发效率。

## 决策
采用 Go 作为后端开发语言。

## 理由
- **单文件部署**：Go 编译为静态链接的原生可执行文件，无运行时依赖，完美契合"单个可执行文件交付"的核心需求。
- **go:embed 内嵌前端**：Go 1.22+ 支持 `go:embed` 指令，可将前端编译产物直接内嵌到二进制中，无需额外部署静态资源。
- **并发模型**：goroutine + channel 天然适合高并发视频流传输和 FFmpeg 进程管理。
- **跨平台编译**：Go 支持交叉编译到 Windows/Linux/macOS，一条命令即可生成目标平台二进制。
- **FFmpeg 调用**：Go 的 `os/exec` 包对子进程的 stdin/stdout 管道管理成熟可靠，适合流式转码场景。
- **SQLite 支持**：Go 生态有 `mattn/go-sqlite3` 等成熟的 SQLite 驱动，支持 WAL 模式。

## 后果
- 前端必须通过 `go:embed` 内嵌，开发阶段需要分别启动前端开发服务器和后端服务。
- Go 缺乏泛型（1.18 引入但生态适配中），部分代码可能存在重复。
- 内存安全性不如 Rust，但在此场景下可接受。

## 备选方案
- **Rust**：性能更优、内存安全，但开发效率低，`go:embed` 等价方案不成熟，编译产物体积较大。
- **Python**：开发快，但无法编译为单文件，依赖管理复杂，GIL 限制并发性能。
- **Node.js + nexe/pkg**：可打包为单文件，但运行时体积大，FFmpeg 进程管理不如 Go 直接。
