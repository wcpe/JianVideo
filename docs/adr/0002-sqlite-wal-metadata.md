# ADR-0002：SQLite WAL 模式作为元数据数据库

## 状态
已接受

## 背景
项目需要持久化存储媒体库元数据（目录、文件信息、用户、转码会话）。候选方案包括 SQLite、内嵌 JSON 文件、PostgreSQL、LevelDB。需要权衡部署复杂度、单用户场景下的性能需求和运维简便性。

## 决策
采用 SQLite WAL 模式作为元数据数据库。

## 理由
- **零配置**：SQLite 内嵌于应用中，无需安装外部数据库服务，契合"无外部依赖"的部署目标。
- **单文件存储**：数据库以单个 `.db` 文件存储，备份恢复简单（直接复制文件）。
- **WAL 模式**：写前日志模式支持读写并发，在转码同时进行媒体库更新时不会阻塞。
- **足够性能**：单用户场景下，10,000 条记录的查询性能完全满足需求（< 500ms）。
- **Go 生态成熟**：`mattn/go-sqlite3` 和 `modernc.org/sqlite` 都是成熟的 Go SQLite 驱动。

## 后果
- 数据库文件需要定期维护（如 VACUUM），但 WAL 模式下可热备份。
- 不支持分布式部署（但本项目不需要）。
- 数据量增长到百万级时可能需要评估迁移方案。

## 备选方案
- **JSON 文件存储**：简单但缺乏事务保证，并发写入不安全。
- **PostgreSQL**：功能强大但需要独立安装和运维，对单用户场景过重。
- **LevelDB/BoltDB**：键值存储，查询能力不如 SQL 灵活。
