# ADR-0045：前端引入 Recharts 图表库

## 状态

已接受

## 背景

第十二期要把统计页（FR-118）扩为「结果 + 趋势」、并新增系统监控页（FR-119），二者都需要**可交互的时序折线图**（hover 看每点精确值、坐标轴、图例、响应式）。现有前端刻意未用图表库（FR-75 统计页用手搓 SVG 横条/进度/热力网格），但真正的折线 + tooltip + 坐标轴若继续手搓，成本高且易出可访问性/交互缺陷。需要决定引入哪个图表库（依赖新增，已与用户确认引入图表库）。

## 决策

引入 **Recharts** 作为前端图表库，统计页（FR-118）与监控页（FR-119）共用。折线 / 面积 / 柱状 / Tooltip / 图例 / 响应式（`ResponsiveContainer`）开箱即用。

## 理由

- **React 原生、声明式**：与现有 React + TS + Mantine 技术栈契合，组件化用法直接，无需为命令式库（如 uPlot）包一层。
- **一库覆盖两页**：统计页的内容趋势（折线/面积/柱）与监控页的系统时序（折线）共用一个依赖，守「简单优先」，不为两页引两个库。
- **数据量适配**：单用户媒体服务器的时序点数有限（按天聚合的内容趋势、可降采样的系统指标），Recharts 性能足够，无需 uPlot 级别的极致优化。
- **交互与可访问性**：内置 Tooltip / 坐标轴 / 图例，省去手搓的可访问性与交互坑。

## 后果

- 新增前端依赖 `recharts`（及其 d3 子依赖），bundle 增大；仅统计 / 监控页引入，由 Vite 按路由 code-split、不拖累首屏。自托管单用户场景对体积不敏感，可接受。
- 图表样式需适配亮 / 暗主题：stroke 用品牌紫 token、坐标轴 / 网格线用 `--mantine-color-dimmed` / `default-border`，不写死颜色。
- 后续若出现 Recharts 难以满足的高频实时刷新性能问题（监控页极端场景），再单独评估是否对该页换 uPlot——本决策不预先为此埋抽象。

## 备选方案

- **uPlot**：~40KB、时序性能最强，但偏低层、非 React 原生需自己包一层、Tooltip/样式手写多，DX 差。仅当监控页高频刷新出现实测性能瓶颈才值得。落选（当前数据量用不上）。
- **Chart.js（react-chartjs-2）**：canvas、默认观感好，但 API 不如 Recharts 声明式贴合 React，且 canvas 在可访问性/与 DOM 主题 token 协同上不如 SVG 直接。落选。
- **继续手搓 SVG**：零依赖，但可交互折线 + tooltip + 坐标轴 + 响应式的手搓成本与维护负担过高，且易出交互/可访问性缺陷。落选。
