# ADR-0043：首页由时间轴改为概览数据看板

## 状态

已接受

## 背景

第一期 FR-A 把媒体「时间轴视图」定为根路由 `/`（首页），并由验收标准 AC-13 固化为「根路由 `/` 默认按添加时间倒序展示媒体（时间轴视图）」。随着功能增多（多库、转码、巡检、统计、监控等），用户进入首页时缺少一个「了解系统整体状况」的入口——时间轴只回答「有哪些媒体」，不回答「媒体库多大、看了多少、系统是否正常、有无在跑的任务」。

本决策把首页改为**系统总览数据看板**，时间轴降为「浏览」组的一个普通入口（`/timeline`）。这与由 FR-A/AC-13 确立的「时间轴即首页」约定相悖，需显式记录取代。该约定此前未单独立 ADR（仅由 FR-A 与 AC-13 承载），故本 ADR 不取代某条具体 ADR，而是取代该**验收约定**——同步修订 AC-13、新增 AC-21（见 PRD §6）。

## 决策

根路由 `/` 渲染「概览」数据看板（KPI 总量 + 媒体构成/各库分布 + 观看概览 + 系统状态 + 任务队列 + 继续观看）；时间轴视图迁至 `/timeline`。看板的总量维度由新增聚合端点 `GET /api/library/summary` 提供，其余维度复用既有端点（stats / system info / health / scan tasks / transcode tasks / continue-watching）。

## 理由

- 看板把分散在各页的关键信号（规模、构成、观看、系统、任务）汇到一处，首页从「一个浏览视图」升级为「系统大盘」，更贴合「个人家庭影音中心」的总览需求。
- 时间轴能力不丢，只是改由导航「时间轴」项进入（`/timeline`），语义更清晰（首页=总览，时间轴=按时间浏览）。
- 总量维度（总占用、总时长、视频/图片拆分、各库聚合）现有端点拿不到，单独加一个纯聚合 SQL 端点即可，不动既有数据模型、不引重型件。

## 后果

- AC-13 修订（不再断言 `/`=时间轴）、新增 AC-21（概览看板验收）。
- 新增只读聚合端点 `GET /api/library/summary`（library 服务层聚合，db 仅读写，符合分层不变量）。
- 既有「首页」相关能力（继续观看 FR-44、那年今日 FR-72）原挂在时间轴页，随时间轴迁至 `/timeline`；概览页另行复用「继续观看」。FR-120 时间轴重做时再统筹时间轴页内的回忆区块。
- 旧书签/深链 `/` 由展示时间轴变为展示概览；时间轴深链改 `/timeline`。`*` 兜底仍回 `/`。

## 备选方案

- **保留时间轴为首页，看板另开 `/dashboard`**：不改 AC-13、改动最小，但「真正的首页=总览」诉求未满足，首页仍是浏览视图。落选。
- **看板与时间轴同页上下拼**：首页过长、两类信息（总览 vs 浏览流）混杂，且时间轴虚拟滚动与看板卡片布局相互干扰。落选。
