# ADR-0005：原生 SMB/CIFS 网络共享支持

## 状态
已接受

## 背景
用户需要播放存储在 NAS（网络附加存储）上的视频文件。候选方案包括：原生 SMB/CIFS 协议支持、要求用户手动挂载 SMB 到本地、NFS 协议支持、WebDAV 协议支持。需要权衡用户体验、实现复杂度和平台兼容性。

## 决策
后端原生支持 SMB/CIFS 协议，用户可直接添加 UNC 路径（如 `\\192.168.x.x\Share`）作为媒体库源。

## 理由
- **用户体验**：用户无需在操作系统中手动挂载 SMB 共享，直接添加网络路径即可。
- **Windows 兼容**：SMB 是 Windows 网络共享的原生协议，Windows 用户无需额外安装任何组件。
- **Go 生态支持**：`github.com/hirochachacha/go-smb2` 等库提供了纯 Go 的 SMB 客户端实现，无需依赖系统级工具。
- **实时监听**：SMB 挂载后的路径可通过 fsnotify 监听，实现与本地目录一致的增量更新体验。

## 后果
- SMB 客户端库在 macOS/Linux 上可能性能不如 Windows 原生 SMB 支持。
- 需要处理 SMB 连接的认证、超时和重连逻辑。
- SMB 路径下的 fsnotify 监听可能不稳定，需要降级为定时轮询作为兜底。

## 备选方案
- **要求用户手动挂载**：最简单但用户体验差，用户需要在操作系统层面操作。
- **NFS 协议**：Linux/macOS 原生支持好，但 Windows 支持需要额外安装。
- **WebDAV**：协议开销大，性能不如 SMB，且需要 NAS 端额外配置。
