# ADR-0058：数据层抽象与外部 PgSQL 可移植路径

## 状态
已接受

## 背景

`docs/PRD.md` §4.2 NFR "数据层可移植"要求：第一版仅用嵌入式数据库（SQLite），但数据访问层要保留未来接入外部 PgSQL 的抽象，不把嵌入式实现硬绑死；真正接入外部库前先写 ADR。

现有决策约束如下：

- ADR-0002 确立 SQLite WAL 模式为元数据数据库，契合"无外部依赖"的自托管部署目标。
- ADR-0023 确认 GORM 为项目唯一 ORM，禁止引入其他 ORM 框架（如 XORM、Ent）。
- `.claude/rules/architecture-invariants.md` §2/§4 锁定 GORM 唯一 ORM、SQLite 驱动（`mattn/go-sqlite3` 或 `modernc.org/sqlite`）、禁止外部消息队列与缓存中间件。

若业务代码直接散落写方言 SQL、直接依赖 SQLite 独有特性，将来一旦有外部数据库需求，迁移会牵动大量业务逻辑。FR2-007 索引基线要跑 1000 万资产压测，向量索引（[ADR-0059](0059-ai-pipeline-vector-index.md)）又天然依赖 SQLite 扩展，需要在架构上先划清隔离边界。

## 决策

第一版**仅使用嵌入式 SQLite**（延续 ADR-0002），**GORM 仍是唯一 ORM**（延续 ADR-0023），同时引入**数据访问抽象（repository 层）隔离业务与具体数据库方言**：

- **repository 接口层**：领域对象的 CRUD 与查询一律经 repository 接口访问；实现层用 GORM + SQLite；business/service 层不直接见方言、不直接持有 `*gorm.DB` 拼 SQL。
- **唯一 ORM 不变**：禁止再引入 XORM、Ent、sqlx 等其他 ORM/查询库，延续架构不变量。
- **可移植约束**：schema 用 GORM `AutoMigrate` 保持可移植子集；尽量只用 GORM 的可移植能力，避免依赖 SQLite 独有语法。
- **隔离标注**：确需 SQLite 独有特性（如特定 `PRAGMA`、全文检索、向量扩展）时，必须把它隔离在可替换的实现点里并显式标注，供未来 PgSQL 侧另行实现；不得散落进通用业务路径。
- **统一经本抽象**：任务队列（[ADR-0055](0055-task-queue-persistence.md)）、Space（[ADR-0056](0056-space-permission-model.md)）的持久化都经本 repository 抽象落库，不各自绕开直连数据库。
- **向量索引隔离**：向量存储（[ADR-0059](0059-ai-pipeline-vector-index.md)）是 SQLite 扩展依赖的典型，必须走隔离点，不允许把向量方言泄漏到业务层。

**明确边界**：1.0 不实现 PgSQL，也不引入任何外部数据库依赖。真正接入外部数据库前，必须另写取代 / 新增 ADR 批准——本 ADR 不批准引入外部数据库库。

## 理由

- 一层薄抽象即可把"用哪种数据库"与"业务怎么用数据"解耦，代价小、收益明确。
- 保留 SQLite 单文件、零配置、可热备的全部优势（ADR-0002），当前自托管单机场景无需外部库。
- GORM 已是既成事实且对 SQLite 支持成熟（ADR-0023），继续沿用避免重写与规则冲突。
- 把 SQLite 独有特性收敛到显式隔离点，将来评估 PgSQL 时改动面可预测、可审计。
- repository 接口让核心查询逻辑可对着接口写测试，符合可测试性与分层单向依赖的质量底线。

## 后果

- 短期多一层 repository 抽象成本：每个领域对象要定义接口与 GORM 实现，代码量略增。
- 换来将来若接入 PgSQL，只需新增实现层，业务代码不被推翻。
- SQLite 独有依赖被强制标注隔离，评审时可一眼看出可移植风险点。
- 接入任何外部数据库前必须先写 ADR，防止静默突破"无外部依赖"边界。
- WAL 模式下的并发读写安全仍是必测高风险区（延续现有约束），抽象层不改变这一点。

## 备选方案

- **直接裸用 GORM + SQLite、不做抽象**：短期最省事，但方言与 SQLite 特性会渗进业务；将来接 PgSQL 需大改业务代码，被否。
- **第一版就同时支持 SQLite + PgSQL 双实现**：可移植性最强，但当前无外部库需求、无证据支撑，双实现与双套测试超出当前范围，违背简单优先，被否。
- **改用非 GORM 方案（sqlx / Ent 等）以获取更强移植能力**：直接违背 ADR-0023 与架构不变量 §2 的唯一 ORM 锁定，被否。
