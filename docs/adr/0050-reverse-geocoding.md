# ADR-0050：地名逆地理编码方案

## 状态
已接受

## 背景
媒体已落库 GPS 经纬度（FR-31），地图页（FR-38）在用。用户希望在时间轴分组头 / 聚合处展示可读地名（如"杭州·西湖"，FR-147）。当前无任何逆地理编码能力，仅有原始坐标。

## 决策
为 GPS→地名提供逆地理编码能力，服务于聚合 / 筛选展示。优先采用**离线方案**（内置粗粒度地名数据集，按经纬度就近匹配到省 / 市 / 区或地标）；具体数据集 / 库在实现期评估后确定（不引入外部消息队列 / 缓存中间件，符合架构不变量）。

## 理由
- 离线方案保护隐私（坐标不外泄）、无网络依赖，契合本地媒体服务器定位。
- 粗粒度地名足以满足聚合展示需求，数据体量可控。
- 逆地理在后端 library 层计算，db 仅读写坐标，保持分层单向依赖。

## 后果
- 需引入离线地名数据集 / 库（体积与许可在实现期评估，必要时补充本 ADR）。
- 地名解析结果可缓存于内存或随媒体记录，避免重复计算。
- 若改用在线 API（备选）需联网与配额，仅作可选项、不作默认。

## 备选方案
- 在线逆地理 API：实现简单但有联网 / 配额 / 隐私问题，不作默认。
- 不做地名、仅显示坐标或"有无位置"：体验差，不满足需求。
