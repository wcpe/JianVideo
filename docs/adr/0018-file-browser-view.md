# ADR-0018：文件目录视图

## 状态
已接受

## 背景
用户需要以传统文件资源管理器风格浏览媒体库中的视频文件，而非仅按添加时间排序的时间轴视图。需要提供按目录层级浏览、面包屑导航、目录树形结构展示的能力。

## 决策
采用「后端扫描文件系统 + SQLite 查询已索引媒体文件」的混合方案实现目录浏览 API，前端采用「侧边栏目录树 + 右侧文件列表 + 顶部面包屑」的经典文件管理器布局。

## 理由
- 后端扫描文件系统获取子目录结构，不额外维护目录树数据库，保持数据模型简洁
- 媒体文件信息从 SQLite 按 `file_path` 前缀匹配查询，只返回已索引的文件，避免返回大量未知文件
- 面包屑由后端构建，前端直接渲染，减少前端路径处理逻辑
- 前端目录树采用懒加载模式，避免一次性递归扫描整个目录树
- 复用已有的 MediaFile 数据模型，不引入新的数据结构

## 后果
- 新增 `GET /api/media/browse` 端点，扩展了 API 契约
- 前端需要创建完整的 React 项目结构（此前 FR-01 只有后端骨架）
- 目录浏览依赖文件系统实时扫描，深层大目录可能有性能问题，后续可优化
- 与 FR-14 共用 `App.tsx`，rebase 合并时需注意路由冲突

## 备选方案
- **纯数据库方案**：在 SQLite 中维护完整的目录树结构，通过递归查询实现。落选原因：增加数据模型复杂度，目录变更需要同步维护，不如直接扫描文件系统简单
- **前端递归请求**：前端逐层请求子目录，自行组装目录树。落选原因：增加前端复杂度和请求次数，面包屑构建需要在客户端拼接路径
