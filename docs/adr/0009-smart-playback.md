# ADR-0009：智能播放策略（直出/转码决策）

## 状态
已接受

## 背景
浏览器无法直接播放所有视频格式。H.264+AAC 的 MP4 是浏览器原生支持的格式，可直接播放；其他格式（H.265、VP9、AV1、MKV 容器等）需要转码为 HLS/TS 流才能在浏览器中播放。需要一个智能决策层，根据媒体文件的编码信息自动选择直出或转码。

## 决策
采用基于容器+视频编码+音频编码的三元组判断策略（mp4+h264+aac → 直出，其他 → 转码），作为播放入口的统一决策点。

## 理由
- 三元组判断是业界标准做法（如 Plex、Jellyfin 等媒体服务器均采用类似逻辑）
- 直出零 CPU 开销、零延迟，用户体验最佳
- 转码模式统一返回 HLS URL，后续可无缝接入真实转码管道
- 逻辑简单明确，易于测试和维护

## 后果
- 正：浏览器兼容格式即时播放，不浪费转码资源
- 负：非兼容格式需等待转码启动，有 1-3 秒延迟（由后续 FR 解决）
- 约束：直出模式需要文件可通过 HTTP 访问，后续需配置静态文件服务

## 备选方案
- **全部转码**：所有格式都走转码管道。落选：浪费资源，浏览器兼容格式无需转码即可播放
- **基于 MIME 类型判断**：依赖 HTTP Content-Type。落选：不够准确，无法反映真实编码格式
- **前端探测**：由浏览器尝试播放，失败后触发转码。落选：增加前端复杂度，首次播放可能失败
