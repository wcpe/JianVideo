# ADR-0038：媒体健康巡检——只读巡检、独立问题表、不复用软删真源

## 状态
已接受

## 背景

媒体库长期运行后会出现"问题媒体"：源文件被外部删除、被截断成 0 字节、视频损坏（ffprobe 无法解析）、缩略图无法生成。FR-73 要求后台扫描这些问题、汇总成可浏览的清单供用户集中处理。

实现时面临几处决策点，都涉及与既有机制的边界，需明确：

- 问题信息存哪里？是否在 `media_files` 上加状态列？
- 巡检的"找不到文件"判定，是否复用 FR-27 全量扫描对账的软删（`deleted_at`）？
- 巡检任务调度，是否复用 FR-29 的扫描任务队列（`scan_tasks` + 单 worker）？

## 决策

- **独立问题表 `media_health_issues`**：问题记录落独立表，**不在 `media_files` 加任何列**。每轮巡检在单事务内先清空全表、再写入当轮问题快照。
- **巡检全程只读**：遍历未软删媒体逐项判定，把结果写入问题表；**绝不改写 `media_files.deleted_at`**。软删 / 回收站是 FR-25/27 的真源与职责，巡检只报告、不联动删除。删除问题媒体复用 FR-69 的批量软删端点。
- **独立后台 goroutine + 状态单例，不复用 `TaskQueue`**：巡检由 `library.HealthService` 用独立后台 goroutine + 单飞标志 + 状态单例 `HealthScanStatus`（结构参照 `scan_status.go`）驱动，不进 `scan_tasks` 队列。
- **新增探测入口，不改既有静默行为**：视频健康用**新增**的 `ProbeVideoHealth(path) error`（跑 ffprobe 判可解析性），缩略图用**新增**的 `TryGenerateThumbnail(path) error`（同步生成捕获错误）；既有的 `probeVideoMetadata`（元数据降级链、失败静默）与异步 `GenerateThumbnail`（只记日志）行为字节级不变。

## 理由

- **解耦与单一真源**：问题清单是"巡检的派生报告"，不是媒体的固有属性；落独立表可独立清空重写、不污染 `media_files` schema，也不与软删 / 扫描 / 收藏等其它轨道在同一张表上耦合演进。
- **不触碰软删真源**：若巡检直接把"找不到文件"写成 `deleted_at`，就与 FR-27 全量对账形成同一事实的第二处写入点，破坏真源一致性（架构红线）。SMB 远程列举不保证完整、误判删除代价高，巡检判 `missing` 也明确排除 `smb://`。只读巡检让发现与处置分离——用户看清单后自行决定是否删除。
- **不复用扫描队列**：`scan_tasks` 队列的语义是"按 `library_id` 排队、单 worker 串行执行扫描"；健康巡检是"单次全局操作、每轮清空重写问题表"，二者粒度与状态模型都不同。硬塞进队列要为它在 worker 里加特例分支（违反开闭原则），不如用与 `scan_status` 同构的轻量独立机制，职责更清晰。
- **判定核心为纯函数**：`classifyMediaIssues` 把 ffprobe / 文件系统 / 缩略图依赖经函数注入，无 IO 副作用，可穷举单测各判定分支，符合质量底线。
- **新增而非改写探测**："读元数据失败可降级"与"判定文件是否损坏"是两种语义，前者静默兜底、后者需要 ok/err 信号。新增独立入口避免改动既有降级链行为、避免回归风险。

## 后果

- 正面：问题清单与 `media_files`、软删、扫描队列彻底解耦，可独立演进；巡检只读、零数据破坏风险；判定逻辑可穷举测试。
- 负面 / 约束：大库逐项 ffprobe / 缩略图生成开销较大，本期单 worker 串行 + 逐项超时，不做并发优化（P7 不镀金）；问题表是当轮快照、不保留历史（重新巡检即覆盖）。后续若需"问题历史趋势"再另立机制，不在本期范围。
- 约束固化：今后媒体健康相关能力一律走 `media_health_issues` 只读报告 + 复用既有删除端点，不得在巡检里改 `deleted_at`，不得把巡检状态塞进 `scan_tasks`。

## 备选方案

- **在 `media_files` 加 `health_status` 列**：落选——把派生报告塞进媒体真源表，污染 schema、与软删 / 扫描在同表耦合，且无法表达"一个媒体多类问题"。
- **复用 FR-27 软删表达"找不到文件"**：落选——破坏软删真源一致性，且把"发现问题"与"删除媒体"强绑定，用户失去先看后删的余地；SMB 误判风险高。
- **复用 FR-29 扫描任务队列调度巡检**：落选——粒度与状态模型不匹配，需在 worker 里加特例分支，得不偿失。
