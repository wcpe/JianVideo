# ADR-0062：采用版本化 Schema 迁移框架保护 v2 升级

## 状态
已接受

## 背景

当前后端主要依赖 GORM `AutoMigrate` 和少量测试来演进 SQLite schema。P2 会一次性引入 Space 归属、任务队列、审计事件、缓存资产、媒体类型、库分型、关键索引和旧数据回填。对于已经使用 v0.20 的用户，升级不能只靠隐式 AutoMigrate：它需要可排序、可重入、可备份、可 dry-run、可校验，并且在失败时能给出清晰中文报告。

ADR-0056 要求历史资源迁入默认 Space，ADR-0055 要求旧扫描/转码队列收敛到通用任务模型，ADR-0058 要求数据访问经 repository 抽象并隔离 SQLite 特性。这些都需要明确的迁移框架承接。

## 决策

引入版本化 schema migration registry，作为 P2 之后数据库结构演进的唯一执行入口。每个迁移步骤使用稳定递增 ID，例如 `20260708_0001_create_spaces`，并提供 `Up`、`Validate`、`Description`、`SafeToRetry`。

迁移状态以 SQLite `schema_migrations` 表记录，字段至少包含迁移 ID、状态、开始时间、完成时间、错误摘要和校验摘要。状态使用 `pending`、`running`、`succeeded`、`failed`。

与 GORM 的关系：

- GORM 仍是唯一 ORM。
- `AutoMigrate` 可以在单个 migration 内作为受控步骤调用，但不得再作为启动时无版本记录的隐式全库升级机制。
- raw SQL 只允许用于明确隔离的 SQLite 优化或索引能力，并需要在迁移描述中标注。

执行语义：

- dry-run 输出将执行的步骤、预计影响范围和阻塞项，不写业务表、不写 `schema_migrations`、不写审计事件。
- 真实迁移前必须创建一致性 SQLite 备份，优先使用 SQLite backup API 或 `VACUUM INTO`；离线复制前必须 checkpoint 并确认没有写入连接。
- 备份完成后必须能打开并通过 `PRAGMA integrity_check`，否则不得继续迁移。
- 迁移步骤尽量在事务内执行；SQLite 不支持安全事务包裹的重型步骤必须明确 `SafeToRetry` 与失败恢复语义。
- 中断后再次执行只能跳过已校验成功的步骤，失败步骤需按 `SafeToRetry` 决定重试或停止。

启动策略：

- 默认策略：对已知安全迁移，服务启动时自动备份、执行、校验；如 dry-run 发现高风险或备份失败，则拒绝进入正常服务并输出中文诊断。
- 管理员可以显式执行 dry-run，用于发版前或大库升级前检查。
- 迁移过程不得移动、重命名或修改原媒体文件。

审计：

- 真实迁移开始、成功、失败写审计事件。
- 审计可靠性与系统级事件 scope 按 ADR-0063 执行。

## 理由

- 版本化迁移能让升级路径可重复、可审计，避免“代码版本变了但数据库怎么变的不可追踪”。
- 把 AutoMigrate 限定在 migration 内，保留 GORM 简单性，同时补足版本记录、dry-run、备份和校验。
- 先备份再迁移是保护用户历史库的最低成本手段，且契合 SQLite 单文件部署形态。
- dry-run 与中文阻塞报告让大库升级可以先评估，不把风险压到启动瞬间。
- 不触碰原媒体文件，保证 schema 升级失败不会损坏用户素材。

## 后果

- 每个 schema 变更都要写 migration 与校验，不能只改 model 后依赖隐式 AutoMigrate。
- 测试需要覆盖排序、dry-run、备份失败、中断重入和旧库 fixture 迁移。
- 启动路径会多一个迁移前置阶段；大库备份和索引重建可能增加首次启动耗时。
- FR2-017 按本 ADR 落地 migration registry、备份、dry-run、失败语义与 AutoMigrate 关系。
- 若用户不接受自动迁移策略，FR2-017 spec 需要改为“默认 dry-run + 管理员确认执行”。

## 备选方案

- **继续只依赖 AutoMigrate**：实现最少，但缺少 dry-run、备份、校验和可重入记录，无法保护 v0.20 升级，被否。
- **每次升级写临时脚本**：短期灵活，但不可组合、不可追踪，长期会积累不可审计升级路径，被否。
- **引入外部迁移工具**：功能成熟，但增加新工具链和依赖；当前 GORM + SQLite 内建能力足够，被否。
- **默认只 dry-run、不自动执行**：最保守，但会让普通自托管用户升级路径变复杂；作为用户可选策略保留，默认不采用。
