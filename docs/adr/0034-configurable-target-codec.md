# ADR-0034：转码目标编码可配置（默认 H.264 不变）


## 状态
已接受

## 背景
FR-06 / [ADR-0003](0003-hls-ts-streaming.md) 将转码输出固定为 HLS/TS + H.264，
单/多码率管道把 H.264 编码器名与 `-pix_fmt yuv420p` 硬编在 `buildArgs`/`buildMultiArgs`。
这保证了 mpegts.js 的广泛兼容，但也意味着系统即便实测可输出 H.265/AV1/VP9（FR-49 已提供
per-codec「系统实测可输出哪些编码」的能力数据），也无法被选用。

FR-50 要让「目标输出编码」成为可配置项，为后续 FR-51（高级编码 fMP4 输出）、FR-52（客户端能力探测）、
FR-53（端到端协商）铺底。这属于对「固定 H.264」这一转码输出决策的扩展，故立此 ADR。

## 决策
转码「目标输出编码」由固定 H.264 改为**可配置**，并满足三条约束：

- **可配置优先级**：服务端以既有 `settings` 表持久化「首选目标编码优先级」（键 `transcode_codec_priority`，
  值为 JSON 数组，如 `["av1","h265","h264"]`）。管道按所选编码参数化输出——编码器名由 FR-49
  `SelectEncoderForCodec(results, codec)` 按编码选硬件优先、无则软件兜底；像素格式与关键编码参数由
  纯函数 `CodecOutputParams(codec)` 映射（h264/h265/av1/vp9）。
- **默认 H.264 不变**：未配置 / 配置为空 / 解析失败一律回落 `["h264"]`；既有入口 `NewPipeline()`
  等价于 `NewPipelineForCodec("h264")`，产出参数与改动前**字节级一致**，运行时默认行为不变、mpegts.js 仍可播。
- **校验限于实测可输出集**：写入优先级时只接受 FR-49 能力 `codecs`（系统实测可输出）并集内、且为管道已知的
  目标编码；含非法 / 不支持 / 重复编码即整体拒绝、不落库。

## 与 FR-06「固定 TS/H.264」的关系
本决策**扩展而非推翻** [ADR-0003](0003-hls-ts-streaming.md)：

- 它只让「视频编码」可配置，**不改输出容器**——playback 仍 `-f mpegts`、ABR 仍 `-f hls`。
  输出容器仍由播放路径决定（FR-06 播放内核 mpegts.js + TS 路径不动）。
- 因此本 FR **不保证**非 H.264 编码端到端可播放：MPEG-TS 无 AV1/VP9 的标准流类型
  （实测 AV1 over TS 被 ffprobe 探测为 `bin_data`），高级编码的容器与播放路径由 FR-51/52
  另以新 ADR 扩展播放内核决策解决。
- 当前阶段「按客户端能力实际选码并切播放路径」属 FR-51/52/53，不在本 FR 范围。

## 理由
- **复用 FR-49 真源**：选码与校验都基于「实测可输出编码」单一真源，避免再造一套能力判断，杜绝漂移。
- **纯函数 + 副作用隔离**：编码→参数映射、优先级校验均为纯逻辑，可穷举单测；设置读写副作用在 settings 服务层。
- **默认不变是硬约束**：以 h264 回落 + 既有 `NewPipeline` 等价，把「可配置」与「默认行为不变」解耦，
  既扩展能力又零回归风险。
- **校验限实测集**：阻止用户配出系统根本编不出的编码，把失败前移到设置写入而非转码运行时。

## 后果
- **正**：转码输出编码可配置，单/多码率管道参数化；为 FR-51/52/53 提供「目标编码」配置入口与管道能力。
- **正**：默认 H.264/TS 行为字节级不变，既有播放与测试零回归。
- **负 / 边界**：本 FR 不交付非 H.264 的端到端播放——非 H.264 over TS 当前浏览器多不可播，
  需 FR-51 的 fMP4/CMAF 输出 + FR-52 的自适应播放器补齐。
- 新增 settings 键 `transcode_codec_priority`；校验所需的「实测可输出集」由调用方从 FR-49 能力服务取，
  settings 不反向依赖 transcoder（保持依赖方向）。

## 备选方案
- **直接按编码切容器（TS↔fMP4）一并做**：会把 FR-51 的播放路径改造提前拉进来，越界且镀金；
  本 FR 只做「配置 + 管道可参数化」，容器/播放留 FR-51。
- **不校验、任意编码都可配**：用户可配出系统编不出的编码，失败延后到转码运行时且难定位；改为写入时按实测集校验。
- **默认即按硬件能力自动选最高级编码**：会改变默认运行时行为、破坏 mpegts.js 兼容；违背「默认 H.264 不变」红线，否决。
