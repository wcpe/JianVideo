## 1. 背景与目标

家庭场景需要按用户/Space 限制可见内容。P5 提供**内容分级**与**可见性策略**，挂在 Space 成员上，而不是全局模糊开关。
## 2. 需求（要什么）

### 2.1 范围内

- **分级枚举**（首批）：`G` | `PG` | `PG-13` | `R` | `UNRATED`（未分级默认策略可配：对受限用户隐藏或可见）。
- 媒体可设 `content_rating`（库内字段；可来自推断/人工；人工优先）。
- Space 策略：
  - 默认最高可见级（如青少年 Space 最高 `PG-13`）。
  - 成员覆盖：某用户在该 Space 的 `max_rating`。
- 列表/详情/播放/搜索/分享创建：一律按调用者有效等级过滤；越权 id 访问 404。
- 管理：owner 可改 Space 默认与成员上限；改级写审计。
- 家长锁：修改策略需二次输入当前用户密码（防小孩乱改）。

### 2.2 不做

- 强制系统级 OS 家长控制对接。
- 基于 AI 自动审核分级（P6 可辅助）。
- 时段锁（可二期）。

## 3. 设计（怎么做）

- DB：`media_files.content_rating`；`space_members.max_rating`；`spaces.default_max_rating`。
- 查询层：媒体 repository 统一注入 rating 过滤，禁止只在 UI 藏。
- 分享：创建时校验资源对创建者可见；公开访问按**分享创建时快照的允许级**或固定「分享不受家长策略限制但禁止 R」——**默认：公开分享链接不受访客家长策略约束，但创建者必须有权看到该媒体**（避免链接成旁路）。若产品要求公开也分级，单列后续。

## 5. 验收标准

- 用户 max=PG 时，R 级媒体不出现在任何列表，直接 API 拉 id 404。
- 修改 Space 策略无密码确认失败。
- owner 始终可管理分级字段。

## 6. 风险 / 待定

- 公开分享与家长策略交互：本 spec 采用「创建者可见即可分享」；若需收紧再开子任务。
- 历史媒体 UNRATED 默认对受限用户是否可见：默认**可见**，可在设置改为隐藏。
