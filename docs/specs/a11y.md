# 功能规格：无障碍与可读性（FR-97）

> 状态：开发中　·　关联 PRD：FR-97　·　分支：feature/fr-97-a11y

## 1. 背景与目标
第九期前端优化在 FR-92~96 已落地设计 token、品牌紫、组件规范、应用框架与动效。
本 FR 在其上做全站无障碍（a11y）与可读性收尾打磨，让键盘用户、移动端用户与
弱视用户都能顺畅使用：焦点可见、触控不误触、文案达 WCAG AA 对比度、长文本可读。
属第九期（P9）前端优化专项，扩 FR-G（界面与可访问性）。

## 2. 需求（要什么）
范围内：
- **焦点可见环**：键盘聚焦（Tab）时可交互元素（按钮/链接/导航项/输入）显示清晰焦点环，
  品牌紫描边（复用 FR-93 主色 token），鼠标点击不显（`:focus-visible` 语义）。
  FR-92 已设 `focusRing:'auto'`，本 FR 在 index.css 用全局 `:focus-visible` 规则补全统一描边。
- **触控目标 ≥44px**：移动端（`@media (pointer: coarse)`）下图标按钮（ActionIcon 等）
  最小点击区放大到 ≥44px，避免误触。
- **对比度核 WCAG AA**：抽查并确认次要文案/徽标/亮色文本达标（dimmed 已由 FR-84/93 处理）。
- **长文本可读**：会溢出的路径/文件名/长标题补 `title` 全文提示与截断（抽查已基本到位，补缺口）。
- **aria 抽查**：图标按钮有 `aria-label`（抽查已基本到位，补缺口）。

不做（范围外）：
- 不大改组件结构、不动业务逻辑、不重排布局。
- 不引新依赖。
- 不改 FR-96 已落地的动效规则。
- 不做完整 axe 自动化无障碍测试基建（YAGNI）。

## 3. 设计（怎么做）
- 全局规则集中在 `frontend/src/index.css` **追加**（不改 FR-96 已有动效块）：
  - `:focus-visible` 选择器给按钮/链接/导航/输入统一焦点环（品牌紫 `--mantine-color-purple-*` token，
    `outline` + `outline-offset`），并显式去掉非 `:focus-visible` 的 outline（鼠标点击不显）。
  - `@media (pointer: coarse)` 下给 `.mantine-ActionIcon-root` 设 `min-width/min-height: 44px`。
- 分散组件仅补必要 `title`（如系统诊断路径行），不改结构。
- 无新 ADR（纯样式与可访问属性补全，不涉架构决策）。

## 5. 验收标准
- `frontend/` 下 `npm run build`(tsc -b) 与 `npm run test`(vitest) 全绿。
- index.css 含 `:focus-visible` 品牌紫焦点环规则、`@media (pointer: coarse)` 下 ActionIcon ≥44px 规则。
- 既有测试（含 FR-96 motion 守护）不回归。
- 【需用户真机确认】键盘 Tab 走查焦点环清晰可见、鼠标点击不残留焦点环；
  移动端图标按钮点击区 ≥44px 无误触；浏览器 a11y/对比度工具抽查次要文案达 WCAG AA。

## 6. 风险 / 待定
- 焦点环全局规则可能与个别 Mantine 组件自带 focus 样式叠加；用 `:focus-visible` + outline 方式
  与 Mantine 的 box-shadow focusRing 并行不冲突（outline 不占布局、不被裁切）。
- 对比度为人工抽查，非自动化穷举，标记为待真机/工具验。
