# 功能规格：登录页打磨

> 状态：开发中　·　关联 PRD：FR-82（扩 FR-13 单用户认证 / FR-14 前端视图）　·　分支：feature/fr-82-login-polish

## 1. 背景与目标

登录页（`frontend/src/pages/LoginPage.tsx`）是用户进入应用的第一屏，当前存在两处体验问题（属第八期界面体验打磨 P8）：

- **空表单时登录按钮的禁用态易被误判为「按钮坏了」**：按钮用 `disabled={!form.isValid()}`，初始空表单时进入 Mantine 默认禁用态——灰得像失效控件，且没有任何提示告诉用户「为什么不能点」，新用户可能以为按钮有故障。
- **整页大片留白、缺品牌图形**：整页仅一张 360px 卡片居中，四周大量空白；品牌仅一行文字标题 `JianVideo`，没有图形 logo，显得空洞、缺辨识度。

目标：在不改动既有登录流程、不碰后端的前提下，让禁用态「可辨且不致误判」，并以一枚原创品牌 SVG 图形充实首屏。

## 2. 需求（要什么）

### 范围内

- **禁用态明确化**：空表单时登录按钮仍禁用（防止无效提交），但必须有明确视觉/文案区分让用户判断这是「未填完」而非「按钮坏了」——按钮下方展示辅助提示文案，并对按钮包裹 tooltip 说明需先填写用户名和密码；表单填妥后提示消失、按钮恢复常态。
- **品牌图形**：新增一枚**原创 SVG** 品牌 logo（简洁、与品牌紫 `purple.4` 协调、视频/媒体主题），置于登录卡片标题上方，消除整页空洞感。
- 可适度强化卡片/背景层次（精准修改、勿大改既有布局）。
- 窄屏不溢出（沿用 `maw="90vw"`）。

### 不做（范围外）

- 不改动登录鉴权流程、不碰后端、不改 auth store。
- 不引入任何第三方插画库 / 图片资产 / 图标库素材（logo 必须原创内联 SVG）。
- 不做注册 / 找回密码 / 多用户等 FR-13 范围外能力。

## 3. 设计（怎么做）

- 新增纯展示组件 `frontend/src/components/BrandLogo.tsx`：内联原创 SVG（视频/媒体主题——播放三角 + 媒体帧轮廓），用品牌紫描边/填充，尺寸由 prop 控制，`role="img"` + `aria-label="JianVideo 标志"` 便于断言与无障碍。**不抄第三方图标库素材。**
- `LoginPage.tsx`：
  - 卡片标题上方渲染 `<BrandLogo>`，居中。
  - 登录按钮保持 `disabled={!form.isValid()}`，外层包 Mantine `Tooltip`（label「请先填写用户名和密码」），并在表单无效时于按钮下方渲染一行辅助 `Text`（如「填写用户名和密码后即可登录」），表单有效时该提示不渲染。
- 纯前端展示层增强，无数据模型 / 接口 / 架构决策改动，**无需新 ADR**。

## 5. 验收标准

- 空表单时：登录按钮处于禁用态，且页面上存在可辨的辅助提示（告知需填写用户名和密码），用户不会误判为按钮故障。（自动化：测试断言按钮 disabled 且辅助提示文案存在）
- 品牌图形：登录卡片上方渲染出品牌 logo 图形元素（自动化：测试断言 `aria-label="JianVideo 标志"` 的 img 角色元素存在）。
- 既有登录流程不回归：填入用户名 + 密码后按钮可点击并触发 `login(...)`，登录成功通知与跳转行为不变。（自动化：沿用既有提交测试 + 新增填妥后按钮可用断言）
- `frontend/` 下 `npm run build`（tsc -b 通过）与 `npm run test`（vitest run）全绿。
- **真机维度（待用户确认）**：浏览器实机打开登录页，肉眼确认 logo 显示、禁用态提示清晰、窄屏不溢出、填妥后可正常登录——单元测试不替代此项。

## 6. 风险 / 待定

- Mantine 禁用按钮不派发鼠标事件，tooltip 悬停可能不触发；故以「按钮下方常驻辅助文案」作为可辨主手段，tooltip 为增强，验收以辅助文案为准。
- 无架构变更，仅新增一个展示组件 + 改动单个登录页文件。
