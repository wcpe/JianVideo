# 功能规格：分档缩略图生成

> 状态：已交付@v0.23.0　·　关联 PRD：FR2-028　·　阶段：P2 `0.23.x`

## 1. 背景与目标

现有缩略图支持 160/320/640、多档 `srcSet`、按需生成和 202 轮询，但生成是进程内 goroutine + semaphore，不持久化、不走通用队列，也没有缓存资产登记和 Space。P2 需要把缩略图作为可重建缓存数据统一管理。

目标：

- 缩略图生成接入任务队列，支持按需/批量、优先级、重试、进度。
- 多档缩略图登记到缓存资产，可清理重建。
- 前端列表与详情继续稳定使用低/高像素缩略图。

前置依赖：FR2-007（Space/索引）、FR2-017（迁移框架）、FR2-037（任务队列）、FR2-048（缓存资产）。

## 2. 需求（要什么）

- 默认尺寸：160、320、640；按设备 DPR 和容器大小选择。
- 支持图片和视频缩略图；视频使用 ffmpeg 抽帧。
- 按需请求缺失缩略图时，JSON/probe 请求返回 202 + 任务信息；图片标签请求继续获得占位或可加载响应，生成完成后真实缩略图返回 200。
- 批量预生成走任务队列。
- 缩略图路径按 Space/media/size 隔离，登记为 `cache_assets(kind=thumbnail)`。
- 清理后可重建，不影响原媒体。
- 范围内：任务化、缓存登记、按需生成、批量预生成、前端兼容。
- 不做（范围外）：智能封面选择（FR2-059）、视频进度预览 sprite/vtt（FR2-029）。

## 3. 设计（怎么做）

任务：

- `thumbnail.generate`：单媒体多尺寸或单尺寸生成。
- `thumbnail.backfill`：批量预生成，按 checkpoint 分批。

服务：

- 请求缩略图先查缓存登记和文件存在。
- 缺失时幂等入队；API probe 返回任务 ID，图片标签路径保持现有占位/轮询兼容行为。
- 生成成功后登记/更新缓存资产。

前端：

- `MediaThumbnail` 保持 `srcSet`，通过现有失败后探测或新增 probe 识别 202/任务状态，继续展示占位与轮询。

## 5. 验收标准

- 160/320/640 三档缩略图按需生成并登记缓存资产。
- 缺失缩略图请求不会阻塞长时间 HTTP 请求；probe 返回可轮询状态，图片标签路径有占位/降级行为。
- 清理缩略图缓存后，访问能重新生成。
- Space A 缩略图路径与任务不影响 Space B。
- `go test`、集成测试、Playwright 缩略图 E2E、`pnpm run quality` 全绿。
- Go 单二进制 serve 后，测试图片/视频缩略图按需生成实跑通过。

## 6. 风险 / 待定

- 已确认：扫描入库时不自动预生成全部尺寸，按需为主，批量预生成可手动触发。
- ffmpeg 路径必须从工具配置读取，不能继续硬编码 `ffmpeg`。
