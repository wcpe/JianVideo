# 功能规格：阶梯快进快退

> 状态：已交付@v0.24.0　·　关联 PRD：FR2-035　·　阶段：P3 `0.24.x`　·　分支：`feature/fr2-035-tiered-seek`

## 1. 背景与目标

素材浏览、粗定位和精细定位需要不同时间尺度的快进快退。固定 ±10 秒既无法逐帧检查，也不适合长视频快速跳转。阶梯 Seek 必须在所有入口保持前后对称、严格夹取边界，并在快速连续操作、Range 请求中止或播放内核切换时避免把受控取消显示为 `Network Error`。

本规格依赖 [FR2-036](fr2-036-player-core.md) 的纯控制层和 `PlaybackBackend` 契约；其中“1 帧”档复用 [FR2-034](fr2-034-frame-stepping.md) 的方向性相邻帧、精确验证与近似降级，不实现第二套逐帧算法。

目标：

- 提供固定且可切换的阶梯集合：1 帧、0.5 秒、1 秒、5 秒、30 秒、60 秒；1 帧档严格复用 FR2-034 的方向性相邻帧语义。
- 同一档位向前、向后完全对称，目标基于后端确认的实际媒体时间计算。
- VOD 和具有滑动窗口的媒体都按实际可 Seek 区间夹取，不产生越界请求。
- 快速连续操作保持最终意图正确，不出现旧结果回写或伪 `Network Error`。

## 2. 需求（要什么）

- 阶梯集合固定为：
  - `1 frame`
  - `0.5s`
  - `1s`
  - `5s`
  - `30s`
  - `60s`
- player-core 不自行选择产品默认档位；Web 壳层在创建控制器时必须从上述集合显式传入初始档位，之后可通过受控命令切换。
- 当前档位属于播放控制状态；按钮、键盘或滚轮只提交“向前/向后”和“切换档位”意图，不直接计算时间。
- 对秒级档位，目标公式固定为：
  - 向前：`clamp(actualMediaTime + step, seekableStart, seekableEnd)`。
  - 向后：`clamp(actualMediaTime - step, seekableStart, seekableEnd)`。
- “向前”和“向后”必须使用同一个当前档位、同一时间基准、同一夹取函数和同一完成判定；除方向符号外不得存在不同算法。
- “1 帧”档必须调用 FR2-034 的逐帧命令，不得换算成固定秒数或复制算法：
  - 除对应边界返回 `clamped=true` 外，`next` 必须到达起始帧之后的第一帧，最终帧严格晚于起始帧；`previous` 必须到达起始帧之前的第一帧，最终帧严格早于起始帧。
  - 精确路径的编号 fixture 必须验证最终帧号恰好为起始帧号 `+1` 或 `-1`；相同帧、反方向和跳号均失败。
  - 支持 `requestVideoFrameCallback` 且具备可靠相邻帧基准时，以实际 `mediaTime` 验证相邻目标时间戳；±1 帧只作时间戳容差，不得放宽方向性或恰好相邻断言。
  - 不支持时明确标记“近似逐帧”，不得用固定秒数路径冒充精确帧档。
- VOD 的边界通常为 `[0, duration]`；直播、追播或滑动 HLS 必须使用后端实时报告的 `[seekableStart, seekableEnd]`，不得假定起点恒为 0。
- 已在边界时继续同方向操作返回成功夹取结果，位置不变，不发起越界 Seek。
- 普通连续阶梯 Seek 采用最后意图优先和请求代次隔离；旧请求被替代后返回 `superseded`，不得覆盖新位置。
- 同一交互批次中的连续方向输入可以合并为等价最终目标，但合并后结果必须与按顺序应用相同档位并逐次夹取的结果一致。
- 切换档位不改变当前播放位置，也不隐式发起 Seek。
- 播放态和暂停态都可执行秒级阶梯 Seek；操作完成后恢复操作前的播放/暂停意图。1 帧档遵循 FR2-034 的方向性相邻帧流程，完成后保持暂停。
- 任何后端路径都不得因边界夹取、旧 Range 请求中止、命令取代、切源或卸载显示 `Network Error`；只有后端确认的真实网络失败才能使用该错误类别。
- Web 保持既有 mpegts.js/MSE、hls.js/MSE 与原文件直出内核，不为阶梯 Seek 新增或替换内核。

**范围内**：

- player-core 的阶梯集合、档位状态、对称目标计算、边界夹取、命令合并、代次隔离和结果模型。
- Web 控件、键盘与 Windows 安装态 PWA 入口到统一命令的映射；其中 1 帧档的 P3 入口仅为 FR2-034 规定的桌面按钮/键盘和 Windows 安装态 PWA。
- 原文件直出、mpegts.js/MSE、hls.js/MSE 路径的阶梯 Seek 回归与错误归类。
- 真实编号帧 fixture、秒级定位 fixture、自动化测试，以及 Windows 桌面 Web 与 Windows 安装态 PWA 的 headed 阻断验收。

**不做（范围外）**：

- P7 原生 Desktop、Android、iOS 播放后端与移动真机验收。

## 3. 设计（怎么做）

### 3.1 档位模型

档位使用封闭联合类型，不接受任意浮点数：

```ts
type SeekTier =
  | { kind: 'frame'; count: 1 }
  | { kind: 'seconds'; value: 0.5 | 1 | 5 | 30 | 60 }
```

- 秒级值以媒体时间秒为单位，不以墙钟时间、播放速率或帧数换算。
- 播放速率不改变 Seek 距离；例如 2 倍速下选择 5 秒仍移动 5 秒媒体时间。
- 档位显示文案由端壳负责，player-core 只保留稳定值。

### 3.2 对称 Seek 算法

```text
读取 PlaybackBackend 已确认快照
  → 取得 actualMediaTime 与实时可 Seek 区间
  → 根据档位计算有符号增量
  → 使用同一 clamp 函数夹取
  → 若目标等于当前位置，直接返回 clamped 结果
  → 否则提交带请求代次的 seek
  → 只接纳当前代次的完成事件
  → 恢复操作前的播放/暂停意图
```

对称性必须通过属性测试证明：在不触及边界且后端准确到达目标时，使用同一档位先向前再向后应回到原位置；先向后再向前也应回到原位置。浮点比较使用媒体时间容差，不直接比较二进制浮点相等。

### 3.3 并发、合并与错误语义

- 每次档位切换和 Seek 命令都进入 player-core 命令流，并携带单调递增代次。
- 未完成的普通 Seek 可被更新的最终意图替代；Web 后端负责中止或忽略旧内核请求，player-core 负责丢弃旧完成事件。
- 命令合并只能合并尚未提交或可安全取代的秒级 Seek；“1 帧”档按 FR2-034 串行执行，每条命令都必须从上一已确认帧取得严格相邻帧，不允许合并后跳过中间确认帧。
- `superseded`、`canceled`、`clamped`、`unsupported` 都是受控结果，不进入错误提示。
- 后端报错必须先按 FR2-036 归类；只有 `network` 类别可显示 `Network Error`。Range 请求因新 Seek 主动中止时必须归为 `superseded` 或 `canceled`。

### 3.4 测试素材与真实验收

- 复用 FR2-034 的 30 fps、10 秒、300 帧真实编号帧 fixture，验证“1 帧”档与 0.5 秒、1 秒、5 秒边界。
- 增加或复用不少于 130 秒的实际编码素材，画面持续烧录媒体时间和帧号，用于验证 30 秒、60 秒往返和尾部夹取。
- 素材必须包含正常 GOP 和非关键帧，并至少通过原文件直出、mpegts.js/MSE、hls.js/MSE 可用路径播放。
- 自动化测试除断言控制器目标外，还须在 headed 浏览器读取后端确认位置；“1 帧”档按 FR2-034 验证方向、编号恰好相邻，并仅以 ±1 帧作为相邻目标 `mediaTime` 的时间戳容差。
- P3 阻断验收固定覆盖 Windows 桌面 Web 与 Windows 安装态 PWA；两者均须在 Windows 实体机以 headed 模式运行，不以 headless、jsdom 或纯 mock 替代。P7 原生 Desktop、Android、iOS 后端与移动真机另行验收。

### 3.5 依赖关系

- 前置依赖：[FR2-036](fr2-036-player-core.md) 的状态快照、Seek 契约、请求代次、受控取消和错误归类。
- “1 帧”档依赖：[FR2-034](fr2-034-frame-stepping.md) 的方向性相邻帧能力、编号恰好 `+1`/`-1` 的精确验证、±1 帧时间戳容差和近似降级。
- Web 播放依赖既有 mpegts.js/MSE、hls.js/MSE、原文件直出与 FR2-026 多码率 HLS，不改变内核选择。
- P7 原生 Desktop、Android、iOS 后端实现基础 `PlaybackBackend` 及所需可选分面，阶梯集合和对称算法继续复用 player-core。

## 5. 验收标准

- 可切换且只可切换到六个固定档位：1 帧、0.5 秒、1 秒、5 秒、30 秒、60 秒。
- 秒级每一档在非边界位置都满足前后对称；同档先前进后后退、先后退后前进均在后端定位容差内回到原位置。
- “1 帧”档完全复用 FR2-034：非边界时 `next`/`previous` 分别严格晚于/早于起始帧，真实编号恰好 `+1`/`-1`，边界按 `clamped=true` 保持原帧；支持 `requestVideoFrameCallback` 时以实际 `mediaTime` 验证相邻目标，±1 帧只作时间戳容差；不支持时明确显示近似降级。
- 选择档位本身不改变位置；播放速率变化不改变各秒级档位的媒体时间距离。
- 所有档位都按后端实时可 Seek 区间夹取；起点向后和终点向前稳定停在边界，返回 `clamped=true`，不发起越界请求。
- 真实编号帧 fixture 上，1 帧档每次 `next` 编号恰好 `+1`、每次 `previous` 编号恰好 `-1`，相邻编号的 `mediaTime` 满足 ±1 帧时间戳容差；0.5 秒、1 秒、5 秒双向结果与烧录帧号/`mediaTime` 对应；长视频 fixture 上，30 秒和60 秒双向定位及尾部夹取正确。
- 快速连续至少 50 次混合档位、混合方向操作后，最终位置与按命令规则计算的最终目标一致；旧 Seek 结果不回写，不出现伪 `Network Error`。
- 原文件直出、mpegts.js/MSE、hls.js/MSE 路径均通过阶梯 Seek 回归，且内核选择与既有行为不变。
- P3 阻断验收在 Windows 实体机的桌面 Web 与 Windows 安装态 PWA 上以 Playwright headed 模式通过；至少覆盖六档、双向、两端边界、连续 Seek、精确逐帧和近似降级。headless、jsdom 或纯 mock 结果不能替代该阻断验收；P7 原生 Desktop、Android、iOS 后端与移动真机不计入 P3 结论。
- player-core 单元测试、属性测试、Web 后端契约测试、真实 fixture 集成测试和工作区质量门全绿。

## 6. 风险 / 待定

- 不同内核对 Seek 完成和实际呈现位置的报告粒度不同，验收必须以后端确认的媒体时间为准，不以按钮点击或预测目标为准。
- 滑动 HLS 的可 Seek 区间会变化，计算目标前必须获取最新快照，否则可能错误夹取到已失效区间。
- 连续 Range Seek 最容易产生预期中止和旧结果竞争，错误归类与请求代次必须作为高风险路径覆盖。
- Web 壳层的初始档位属于产品交互选择，不由 player-core 擅自设定；实现时须由调用方显式传入固定集合中的值。
