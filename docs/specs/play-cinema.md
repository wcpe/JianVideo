# 功能规格：播放页操作收纳与影院模式

> 状态：开发中　·　关联 PRD：FR-85（扩 FR-30，新增播放页影院态）　·　分支：feature/fr-85-play-cinema

## 1. 背景与目标

播放页（PlayPage）头部把全部操作平铺一行——返回、标题、改显示名、改文件名、下载、分享、外部播放器、加入预生成，右侧字幕菜单。窄屏（≤480）下按钮换行铺满多行、长标题挤压按钮，可用性差。同时播放页在桌面端始终被左导航占宽，视频可视区偏小，缺少「专注观影」的入口。属第八期（P8）界面体验打磨。

## 2. 需求（要什么）

- **P7 操作收纳**：头部次要操作收进「更多 ⋯」Menu。
  - 保留在外：返回、字幕菜单。
  - 收进「更多」Menu：改显示名、改文件名、下载、分享、外部播放器、加入预生成。
  - 窄屏头部不再换行铺满多行、无横向滚动、长标题不挤出按钮。
- **P11 影院模式（方案 A：仅临时收起左导航）**：播放页提供显著入口临时收起/隐藏左导航让视频区变宽。
  - 用播放页本地态，**不复用全局 `useNavCollapsed`、不写 localStorage、不污染全站持久态**。
  - 切出影院态或离开播放页自动恢复全站导航原状。
- 范围内：纯前端、PlayPage 头部布局重排、影院态本地态与 AppShell 协作机制。
- 不做（范围外）：碰后端、引入新依赖、改全局 `useNavCollapsed` 的持久语义、视频播放/续播逻辑改动。

## 3. 设计（怎么做）

- 新增 `CinemaContext`（React Context）：`{ cinema: boolean; setCinema: (v: boolean) => void }`，默认 `cinema=false`、`setCinema` 空操作（无 Provider 时安全降级）。
- `AppLayout` 用本地 `useState` 持有 `cinema`，经 Provider 下发；导航的**有效收缩态** = `navCollapsed || cinema`。
  - 持久态真源仍是 `useNavCollapsed`：影院态只影响"有效收缩"的临时叠加，从不写 localStorage、不改 `navCollapsed` 本身。
  - 兼容 FR-83 分组渲染：`renderNavGroups` 仍按有效收缩态切换展开/收缩，分组结构不变。
- `PlayPage` 消费 `CinemaContext`：
  - 头部新增显著入口按钮「影院模式 / 退出影院」切换 `cinema`。
  - `useEffect` 清理函数在卸载时 `setCinema(false)`——离开播放页自动恢复。
- 头部用 `Menu` 收纳次要操作：返回 + 标题 + 「更多 ⋯」+ 影院按钮在一组，字幕菜单在右；改名/下载/分享/外部播放器/加入预生成作为 `Menu.Item` 打开各自既有弹窗（弹窗组件与回调不变）。
- 无新 ADR：仅前端组件内状态与 Context，未触及架构不变量。

## 4. 任务拆分
- [ ] 新增 `CinemaContext` 与 Provider 接入 `AppLayout`，有效收缩态 = `navCollapsed || cinema`
- [ ] PlayPage 头部次要操作收进「更多」Menu，保留返回 + 字幕菜单
- [ ] PlayPage 影院模式按钮切换 cinema，卸载自动恢复
- [ ] 测试：Menu 收纳与点击触发弹窗、影院态切入/切出 DOM/状态变化、AppLayout 有效收缩
- [ ] 文档同步：PRD 状态、CHANGELOG

## 5. 验收标准
- 窄屏（≤480）头部不铺满多行、无横向滚动；次要操作在「更多」Menu 内可点开并触发对应弹窗（改名/下载/分享/外部播放器/加入预生成）。
- 影院态切入：导航有效收缩、视频可视区变宽；切出或离开播放页全站导航恢复原状（localStorage 不被写入、其它页面不受影响）。
- 回归：FR-30/42/43/77/79 头部操作弹窗功能不变、续播上报（FR-44）不受影响。
- 自动化：vitest 断言「更多」Menu 收纳次要操作且点击触发、影院态切入/切出的 DOM/状态变化、AppLayout 有效收缩。
- 真机（待真机验）：桌面切入影院态视频区明显变宽、退出恢复。

## 6. 风险 / 待定
- 影院态为播放页本地态，依赖 PlayPage 卸载清理恢复；若未来 PlayPage 不再整页卸载需复查恢复时机。
