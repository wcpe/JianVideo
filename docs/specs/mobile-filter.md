# 功能规格：移动端筛选折叠

> 状态：开发中　·　关联 PRD：FR-86　·　分支：feature/fr-86-mobile-filter

## 1. 背景与目标
时间轴页（`TimelinePage`）与目录浏览页（`BrowsePage`）的筛选区在窄屏下纵向堆叠、控件换行溢出，把媒体列表推到很下，移动端首屏看不到缩略图。本 FR（P8 界面体验打磨）将移动端筛选控件收进「筛选」抽屉、搜索框常驻，使首屏直达媒体。扩 FR-36（结构化筛选）/FR-45（移动端响应式）。

## 2. 需求（要什么）
- 移动端（< `sm` 断点）：除搜索框外的筛选控件收进一个「筛选」抽屉（`Drawer`），由一个「筛选」触发按钮打开；搜索框常驻在抽屉之外。
- 桌面端（≥ `sm` 断点）：布局与行为保持不变（筛选区内联铺开，无抽屉、无触发按钮）。
- 抽屉内的筛选项与桌面内联筛选项共用同一套受控状态：展开抽屉调整设置仍正确带进请求、收起后保留已选。
- `TimelinePage` 与 `BrowsePage` 都达到该移动端效果。
- 范围内：仅新增「响应式容器（Drawer + 触发按钮 + 断点显隐）」。
- 不做（范围外）：不动既有受控筛选逻辑（收藏/标签/类型/大小/日期/缩放的 state 与请求拼装）、不动搜索防抖（各 400ms）、不引新依赖、不碰后端。

## 3. 设计（怎么做）
- 复用项目既有移动端抽屉惯例（见 `AppLayout.tsx`：`Burger hiddenFrom="sm"` + `Drawer hiddenFrom="sm"` + 内容 `visibleFrom="sm"`）。
- 用 `@mantine/hooks` 的 `useDisclosure` 控制抽屉开合，Mantine `Drawer` 承载筛选控件。
- 把四个筛选区块（收藏/标签、类型/大小/日期、时间轴缩放等）抽为页面内的一段共享 JSX（受控子组件，props 不变），桌面以 `visibleFrom="sm"` 内联渲染，移动以「筛选」按钮（`hiddenFrom="sm"`）打开 `Drawer`（`hiddenFrom="sm"`）承载同一段控件。控件本身受控，状态由页面持有，避免逻辑重复。
- 搜索框（`TextInput`）保持原位常驻，不进抽屉。
- 无新 ADR（仅前端响应式容器，不触动架构决策）。

- 桌面（≥sm）：`TimelinePage.filter.test.tsx` 既有断言全绿（请求带 favorite/type/size_min/tag_id 不变）。
- 移动端：存在「筛选」抽屉触发器；搜索框在抽屉外常驻；展开抽屉调整筛选项后请求仍带对应参数；收起后已选保留。

- 真机维度（待真机验）：iPhone/Android 浏览器或 DevTools 375px 宽，确认首屏可见 ≥1 行缩略图、筛选抽屉可展开收起。
