# 功能规格：左侧导航分组

> 状态：开发中　·　关联 PRD：FR-83（扩 FR-54）　·　分支：feature/fr-83-nav-grouping

## 1. 背景与目标

左侧导航现为单层平铺 11 项（管理 / 时间轴 / 目录 / 相册 / 地图 / 回收站 / 巡检 / 重复项 / 统计 / 转码 / 系统），随功能增多查找成本上升。按「浏览 / 管理 / 系统」三组分组并加分隔，让用户更快定位。属第八期（P8）界面体验打磨。

## 2. 需求（要什么）

- 左导航按三组分组并加视觉分隔：
  - **浏览**：时间轴、目录、相册、地图、统计
  - **管理**：管理（存储库）、回收站、巡检、重复项、转码
  - **系统**：系统
- 桌面 Navbar 与移动 Drawer 都按分组渲染。
- 范围内：纯视觉分组 + 组间分隔；收缩态（64px）不破版；命令面板复用导航项不受影响。
- 不做（范围外）：可折叠分组、拖拽排序、分组持久化；不碰后端、不增数据模型 / 接口。

## 3. 设计（怎么做）

纯前端，仅改 `frontend/src/components/AppLayout.tsx`：

- 保留既有扁平数组 `navItems`（11 项，路径 / 顺序 / 语义不变）作为**命令面板 flat map 的唯一来源**（FR-74 不回归）。
- 新增只读分组结构 `navGroups: { title, items }[]`，其 `items` 直接引用 `navItems` 中的成员（不复制项，靠按 path 取子集），仅用于渲染。
- 抽出 `renderNavGroups(onNavigate?, collapsed)` 复用于桌面 Navbar 与移动 Drawer：
  - 展开态：每组前渲染一个 `dimmed` 小标题（`Text size="xs" c="dimmed"`），组内项沿用现有 `renderNavLink`。
  - 收缩态：标题文字不显（64px 放不下），改用 `Divider`（首组前不加）分隔，图标仍居中可点、Tooltip 沿用现有逻辑——不破版。
- 不涉及架构决策，无新 ADR、无新依赖。
