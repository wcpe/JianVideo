# 功能规格：手动清晰度、省流量、变速与 A-B 循环

> 状态：已交付@v0.24.0　·　关联 PRD：FR2-057　·　阶段：P3 `0.24.x`

## 1. 背景与目标

FR2-026 已提供 HLS 多码率产物和 hls.js 自动码率切换，当前播放器只展示实际 ABR 档位，不允许用户手动锁档，也没有省流量约束。现有 Web 播放器已有基础倍速控件，但尚未形成 P3 `player-core` 的统一状态与验收契约；A-B 循环仍缺失。

本功能在不替换 Web 解码内核、不引入自定义 ABR 算法的前提下，补齐手动清晰度、自动模式、省流量、0.5–2 倍速和 A-B 循环，并把控制语义下沉到 ADR-0057 定义的 `packages/player-core`，由 Web `PlaybackBackend` 适配 hls.js、mpegts.js 和原生 video 能力。

目标：

- 自动与手动清晰度切换行为明确、可观察、可降级。
- 省流量模式硬性限制最高 480p，并在用户主动播放前、暂停期间关闭主动分片预加载。
- 倍速和 A-B 循环在清晰度切换、缓冲与 seek 后保持稳定。
- 通过弱网与真实浏览器验收，而非只依赖 jsdom 或 hls.js 测试桩。

前置依赖：FR2-026（ABR HLS）、ADR-0026（hls.js 内核）、ADR-0057（player-core 边界）。

## 2. 需求（要什么）

### 2.1 清晰度模式

- HLS master manifest 可用时，清晰度菜单必须提供“自动”和 manifest 中实际可用的手动档位。
- 默认模式为“自动”，由 hls.js 内置 ABR 根据吞吐、缓冲和错误状态选档；项目不实现第二套 ABR 算法。
- 手动选择档位后锁定对应 hls.js level，界面同时显示“手动”状态和实际播放档位。
- 选择“自动”后解除手动 level，恢复 hls.js ABR；界面显示当前实际档位，但不得把实际档位误标成手动选择。
- level 列表以 manifest 实际数据为准；不展示高于源分辨率或未生成的虚假档位。
- 同一高度存在多个变体时，菜单可显示码率区分；若只显示一个高度，默认选择该高度中带宽最高的可用变体。
- level 索引只在当前 hls.js 实例生命周期内有效；跨 manifest 刷新或播放源切换时必须按高度/带宽语义重新匹配，禁止持久化旧索引。

### 2.2 省流量模式

- 省流量开启时，自动模式最高只能选择 480p；存在多个 480p 变体时以不超过 480p 的最高可用变体作为 ABR 上限。
- 省流量开启且手动模式选择 480p 以下档位时，保持该手动档位。
- 用户手动选择高于 480p 的档位时，必须先自动关闭省流量，再切换到目标档位；界面给出一次明确提示，禁止出现“省流量已开但实际播放 720p/1080p”的矛盾状态。
- manifest 没有任何不高于 480p 的档位时，必须停止 HLS 播放与后续分片调度，并明确提示“当前视频无 480p 或更低档位，请关闭省流量后播放”；在用户关闭省流量前不得例外播放最低档或任何更高档位。
- 省流量关闭时清除 ABR 上限和“无兼容档位”阻断；若当前为自动模式，恢复完整自动档位范围；若当前为手动低档，保持用户手动选择。恢复播放仍遵守浏览器自动播放策略和用户原播放/暂停意图。
- 省流量不做服务端转码自动触发；缺少低档位时只停止播放并提示关闭省流量，按需补转码另属转码策略规格。

### 2.3 关闭主动预加载

省流量开启时，“关闭主动预加载”定义为：

- 播放器进入页面后可加载 master manifest 以枚举档位，但在用户明确点击播放前不得请求媒体分片。
- Web video 元素使用 `preload="none"`；hls.js 使用 `autoStartLoad=false`、`startFragPrefetch=false`，仅在用户播放动作后调用 `startLoad()`。
- 暂停后停止继续调度新分片；允许已经发出的请求完成，但其后不得持续扩大缓冲。恢复播放时再调用 `startLoad()`。
- 省流量开启时禁止静音自动播放，因为自动播放会绕过“用户明确点击后才开始分片加载”的约束。
- 对非 HLS 后端，若不能只加载 manifest，则整个媒体后端初始化推迟到用户点击播放；不得为了探测时长提前拉取完整流。
- 正常播放期间仍允许维持避免卡顿所需的有限前向缓冲；“关闭主动预加载”不等于逐分片等待播放头到达，也不得通过把缓冲降为零制造持续卡顿。

### 2.4 倍速

- 倍速范围为 0.5x–2x，固定提供 `0.5、0.75、1、1.25、1.5、1.75、2` 七档。
- 倍速只通过 `QualityFacet.setPlaybackRate` 应用，Web 适配层映射到 `HTMLMediaElement.playbackRate`；基础 `PlaybackBackend` 不提供倍速方法。
- 切换清晰度、hls.js 重新 attach、短暂缓冲恢复后保持当前倍速；切换到新媒体时重置为 1x。
- 后端不支持某倍速时返回能力不足，由 UI 回退 1x 并提示；不得显示已选 2x 但实际仍为 1x。
- P3 不跨设备同步倍速，也不把倍速写入观看历史。

### 2.5 A-B 循环

- 用户可在当前播放位置依次设置 A 点和 B 点；完整区间满足 `0 <= A < B <= duration`，最小长度为 0.5 秒。
- 只设置 A 时不循环；设置合法 B 后立即启用循环。
- 仅当实际 `currentTime >= B` 时 seek 回 A 点并继续保持原播放/暂停状态和倍速；不得以提前阈值在到达 B 前回跳。
- B 点小于等于 A、区间不足 0.5 秒、时长未知或位置非法时拒绝设置并给出可理解提示，不改变已有合法区间。
- 用户 seek 到区间外不自动清除循环；若 seek 到 B 点之后，播放器应立即回到 A 点。只有“清除 A-B”、切换媒体或媒体失效时才关闭循环。
- 清晰度切换、ABR 自动降档和短暂网络恢复不得清除 A/B；切换到不同 `media_id` 时必须重置。
- A-B 只属于当前播放会话，不写入跨设备观看状态，不增加额外观看次数。

### 2.6 范围外

- 不新增转码 ladder，不保证服务端一定存在 480p 产物。
- 不自研 ABR 算法，不替换 hls.js、mpegts.js 或既有 fMP4/CMAF 路径。
- 不实现音频变调、逐帧 A/B 导出、循环片段下载、跨设备同步播放器偏好。
- 不把倍速或 A/B 区间配置写入 FR2-045 的观看历史真源；循环回跳仅通过 `reason=ab_loop` 区分控制来源。

## 3. 设计（怎么做）

### 3.1 player-core 状态

`player-core` 维护与端无关的控制状态，至少包括：

- `qualityMode: 'auto' | 'manual'`
- `manualQuality?: { height: number; bandwidth?: number }`
- `actualQuality?: { height?: number; bandwidth?: number }`
- `dataSaver: boolean`
- `dataSaverBlocked: boolean`，仅表示省流量开启但不存在 `<=480p` HLS 档位
- `playbackRate: number`
- `abLoop: { a: number | null; b: number | null; enabled: boolean }`

状态机负责模式转换、严格 480p 上限、无兼容档位阻断、手动高档关闭省流量、倍速范围和 A-B 合法性；Web 组件只渲染状态并转发用户动作，不在 JSX 内重复规则。

按照 FR2-036 的 `PlaybackBackend` 可选能力扩展机制，清晰度与倍速能力统一通过 `QualityFacet` 提供，包括枚举清晰度、设置自动模式、设置手动档、设置 ABR 上限和 `setPlaybackRate`；加载调度能力通过 `LoadControlFacet` 提供，包括开始加载、停止加载和查询加载状态。A-B 回跳继续使用基础 `PlaybackBackend.seek`，基础接口不增加倍速方法。facet 不可用时返回结构化能力不足结果，由核心执行可见降级，页面组件不得直接操作 hls.js。

### 3.2 hls.js level 约束

仅使用 hls.js 公共 API，不访问私有字段：

- manifest 解析后读取 `hls.levels` 建立菜单和语义映射。
- 自动模式设置 `hls.currentLevel = -1`。
- 手动模式设置 `hls.currentLevel = matchedIndex`，使用户动作立即切换；后续不得由组件自行把它改回 `-1`。
- 正常自动模式设置 `hls.autoLevelCapping = -1`，表示不额外限档。
- 省流量自动模式计算最高的 `height <= 480` level 索引，并设置 `hls.autoLevelCapping = capIndex`；若没有符合项，立即调用既有暂停能力停止 HLS 播放，通过 `LoadControlFacet` 停止加载，设置 `dataSaverBlocked=true` 并提示关闭省流量，禁止选择最低 level 作为例外。
- 监听 `LEVEL_SWITCHED` 更新实际档位；实际档位只是观测值，不反向覆盖用户选择。
- 监听 manifest/level 更新后重新匹配手动语义档位和省流量 cap；不得假设 level 索引跨清单稳定。
- 禁止写 `nextAutoLevel` 等用于 ABR 内部估算的值，避免与 hls.js 吞吐算法争用。

模式转换顺序：

1. 自动 → 手动：校验目标仍可用；若目标高于 480p，先关闭省流量并清除 cap，再设置 `currentLevel`。
2. 手动 → 自动：设置 `currentLevel=-1`；省流量关闭时设置 cap 为 `-1`，省流量开启时重新计算 480p 上限，无兼容档位则进入播放阻断。
3. 开启省流量：关闭自动播放与主动预加载；自动模式设置 cap，手动高于 480p 时降到最高可用 `<=480p`；无兼容档位时停止播放与加载并进入阻断态，不允许最低档例外。
4. 关闭省流量：设置 `autoLevelCapping=-1`，清除阻断态；不擅自改变合法的手动档位，并按原播放/暂停意图决定是否恢复加载。

### 3.3 不可用与错误降级

- 播放路径不是 HLS master、hls.js 不支持、manifest 只有单档或 level 信息缺失时，清晰度菜单显示“原画/不可切换”，不展示无效手动档位。
- 用户保存的语义档位在新 manifest 中不存在时，仅当 `dataSaver=false` 才选择不高于目标的最近档；若没有更低档，可选择 manifest 的最低可用档，并提示实际降级结果。
- `dataSaver=true` 时，manifest 刷新、档位失效和实例重建都必须先把候选集合过滤为 `height <= 480`，再在该集合内重匹配自动 cap 或手动档；过滤后无合规档位时立即停止 HLS 播放与加载并进入阻断态，绝不回退到 manifest 的最低高档。
- 手动档播放失败时，`dataSaver=false` 可先降到下一可用低档并保持手动模式，没有更低档时切回自动；`dataSaver=true` 只能在 `<=480p` 合规集合内降级，集合为空时阻断播放。连续 fatal 错误再沿用既有播放路径 fallback，不在本功能复制错误恢复器。
- 省流量 cap 对应 level 暂时失效时，重新计算不高于 480p 的可用档；没有时立即停止 HLS 播放与加载并进入阻断态，持续提示关闭省流量，严禁请求或播放更高档位。
- hls.js 实例重建后，按语义状态重新应用 cap、手动档、加载阻断和倍速；失败时 UI 必须以实际后端状态为准。

### 3.4 A-B 循环执行

- 核心以秒保存 A/B，Web 后端监听高频时间更新；至少结合 `timeupdate` 与 seek 后检查，避免只依赖低频 UI 渲染。
- 当且仅当实际 `currentTime >= B` 时，执行一次受保护的 `seek(A)`；seek 完成前不重复触发，防止循环调用。回跳后端确认位置与 A 点相差不超过 0.1 秒即可视为落点成功，0.1 秒只作为落点容差，不能作为提前触发阈值。
- A/B 在媒体已知 duration 后夹取校验；duration 变化导致区间非法时关闭循环并提示。
- 循环回跳必须以 FR2-045 定义的 `reason=ab_loop` 发起和上报，不创建新会话，也不得触发完成判定或 `view_count` 增长；正常播放进度仍可记录当前位置。

### 3.5 UI 与可观测性

- 清晰度菜单同时表达用户模式与实际档位，例如“自动（当前 480p）”“720p（手动）”。
- 省流量开关附近说明“最高 480p，暂停和播放前不预加载”；无 `<=480p` 档位时常驻显示关闭省流量提示，并保持播放阻断到用户关闭省流量或切换媒体。
- A-B 控件明确显示 A、B 时间和启用状态，并提供单步“清除 A-B”。
- 错误和降级提示使用中文，不输出 hls.js 内部对象、URL token 或隐私参数。
- 不使用 `console.log` 代替正式日志；诊断事件按现有前端日志/遥测机制记录模式、目标高度、实际高度和降级原因。

## 5. 验收标准

### 5.1 自动化验收

- manifest 含 1080p/720p/480p 时，菜单展示实际档位；自动模式 `currentLevel=-1`，手动选择后锁定对应 level，切回自动恢复 ABR。
- 开启省流量后，自动模式的实际请求不高于 480p；手动选择 720p/1080p 会先关闭省流量并清除 cap。
- 没有 480p 或更低档时停止 HLS 播放与分片调度，显示关闭省流量提示；关闭省流量前不得请求或播放最低档及任何更高档位，也不得崩溃或无限切档。
- 省流量页面在用户点击播放前只允许 manifest/必要元数据请求，不得发出媒体分片请求；暂停且在途请求结束后，连续 10 秒不再出现新分片请求。
- 倍速七档均只通过 `QualityFacet.setPlaybackRate` 正确映射到 Web 媒体能力；基础 `PlaybackBackend` 无倍速方法，清晰度切换和 hls.js 重建后保持倍速，新媒体重置 1x。
- A/B 合法性、0.5 秒最小区间、仅在 `currentTime>=B` 时回跳、A 点 0.1 秒落点容差、seek 到区间外、清晰度切换保持和切换媒体重置均有测试。
- A-B 回跳使用 `reason=ab_loop`，不会触发完成状态或 `view_count` 增长。
- 手动档不可用时，`dataSaver=false` 可按“最近低档 → 最低档 → 自动”的规则降级；`dataSaver=true` 必须先过滤 `<=480p`，仅在合规集合内重匹配，无合规档位时阻断播放。UI 模式、阻断状态与实际后端状态一致。
- 既有直连优先、mpegts.js 追播、fMP4、续播、字幕和播放错误 fallback 测试保持通过。

### 5.2 弱网与真实浏览器验收

- Playwright 使用真实 Chromium 和真实 master manifest/分片，不只 mock hls.js；通过浏览器网络条件模拟约 1 Mbps 下行、150 ms RTT、禁用缓存。
- 自动模式从高档播放时，在弱网下可观察到 `LEVEL_SWITCHED` 降档，播放不中止为 fatal error，并在网络恢复后允许 hls.js 自主升档。
- 省流量模式在同一弱网条件下始终不请求高于 480p 的变体；若 fixture 无 `<=480p` 档位，必须停止播放和分片调度并提示关闭省流量，关闭前网络中不得出现更高档媒体分片。
- 手动高档在弱网下可锁定；若该 level 发生不可恢复错误，按规格降级且播放器继续可操作。
- 真实 Chrome 或 Edge 手动验收（需用户确认）：
  1. 切换自动、各手动档和省流量，核对界面档位与 DevTools Network 实际变体请求一致。
  2. 开启省流量刷新页面，确认点击播放前无分片；播放后暂停，确认在途请求结束后不继续下载新分片；加载无 `<=480p` 档位的真实 HLS 媒体，确认播放被阻断且关闭省流量前无高档分片。
  3. 在 0.5x、1x、1.5x、2x 下分别播放并切换清晰度，声音与画面持续、实际倍速不复位。
  4. 设置不少于 3 秒的 A-B 区间，在 0.5x、1x、2x 下各循环至少 3 次，确认每次实际到达 B 后才回跳、落点在 A 点 0.1 秒容差内、清晰度切换后仍保留，且观看状态不误完成。
- 安装态 PWA 阻断验收（需用户确认）：从系统入口启动并确认 `display: standalone`，使用真实 HLS manifest、真实媒体分片和真实媒体元素重复上述省流量、预加载、倍速与 A-B 流程；至少核对一次无 `<=480p` 档位阻断和一次 `ab_loop` 不误完成。普通标签页、headless、jsdom、mock 媒体或测试桩不能替代该验收。

## 6. 风险 / 待定

- 已确认：省流量严格最高 480p，并关闭用户主动播放前与暂停期间的主动预加载；手动选择更高档自动关闭省流量，无 `<=480p` 档位时停止 HLS 播放，不存在更高档例外。
- hls.js level 可用性会因冗余流、错误恢复和清单刷新变化，必须保存语义档位而非长期保存数组索引。
- 不同浏览器对 `preload` 和暂停后的网络调度存在差异，验收以 Network 实际分片请求为准，不只检查属性值。
- `timeupdate` 频率不足以保证帧级 A-B 精度；P3 只允许实际到达 `currentTime>=B` 后触发回跳，0.1 秒仅为 A 点落点容差，不承诺逐帧无缝循环。逐帧剪辑级循环需另立规格。
- 弱网自动化受运行机性能影响，测试应断言 level 趋势、请求档位和 fatal 状态，不以单次卡顿毫秒数作为唯一门禁。
