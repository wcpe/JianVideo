# 功能规格：设置页改进（结构化编辑与分区）

> 状态：开发中　·　关联 PRD：FR-87（扩 FR-24/FR-55/FR-56）　·　分支：feature/fr-87-settings-improve

## 1. 背景与目标
设置页（`frontend/src/pages/SettingsPage.tsx`）目前存在三处可用性短板，属第八期（P8）界面体验打磨：

- 「每盘符回收站路径」是裸 JSON `Textarea`，普通运维需手写 JSON，易拼错、无校验。
- 全部设置项混在第一张卡片里（扫描周期/回收站/网络代理共用一个保存按钮），与工具路径、环境变量两块缺乏一致的分区结构。
- 环境变量区只读展示 `JWT_SECRET`，未设置时（启动随机生成、重启需重登）用户无任何提示，容易忽略持久化会话的建议。

本次改进只动前端展示与交互，**后端契约与后端测试一律不动**。

## 2. 需求（要什么）
- **P9 回收站键值编辑器**：把裸 JSON 文本框改为结构化「盘符→路径」行列表编辑器（可增/删行，每行 盘符 + 路径 两个输入）。前端把行序列化为 JSON 字符串提交，后端 `recycle_bin_paths` 存 JSON 串的契约保持不变。加载既有 `{"D":"D:/.recycle"}` 能回填为对应行；空盘符或重复盘符给行内校验且不提交。
- **P10 设置分区**：把设置项按「扫描 / 网络 / 工具路径 / 回收站」分区（各有分区标题/容器），环境变量保持只读区。保持单一「保存设置」按钮统一 PUT 全部键（后端 SetMany 单事务，不拆成多次提交）。
- **P17 JWT_SECRET 警示**：消费 `GET /api/system/env` 返回的 `JWT_SECRET`（`sensitive=true`、`set=false`）时，在环境变量区对该项显内联警示（提示未设置会导致每次重启需重新登录、建议设置 `JWT_SECRET` 环境变量持久化会话）；`set=true` 时不显。

- 范围内：纯前端 `SettingsPage.tsx`，必要时 `frontend/src/api/settings.ts`、`frontend/src/mocks/handlers.ts`、`SettingsPage.test.tsx`。
- 不做（范围外）：后端契约/后端测试改动；路径存在性校验、磁盘探测等后端能力（YAGNI）；设置页写入/持久化 JWT_SECRET（敏感/启动期项只读，越界且有安全风险）。

## 3. 设计（怎么做）
- 回收站编辑器：以本地 `Array<{drive, path}>` 状态承载行，加载时把既有 JSON 字符串解析为行（解析失败回退空行）。保存前用纯函数把行序列化回 `{drive: path}` JSON 字符串；空盘符/重复盘符行内标红、阻止提交（不调用 PUT）。提取行↔JSON 转换为纯函数便于单测。
- 分区：用四个带标题的 `Card` 区块（扫描 / 网络 / 工具路径 / 回收站）承载对应字段，共用一个 `handleSave` 与单个「保存设置」按钮统一 PUT 全部键（`SetMany` 单事务语义不变）。
- JWT_SECRET 警示：在环境变量表对 `key==='JWT_SECRET' && !set` 的行内联渲染 `Alert`/警示文案；不改 env 接口、不新增可写入口。
- 无新 ADR：未引入新技术/新模式/未推翻既有决策。

## 5. 验收标准
- `frontend/` 下 `npm run build`（tsc -b）与 `npm run test`（vitest）全绿。
- 回收站编辑器：能增/删行、回填既有 JSON、空/重复盘符行内校验且不提交（无效时不发 PUT）；有效时序列化为正确 JSON 串提交。
- 设置页出现「扫描 / 网络 / 工具路径 / 回收站」分区标题且字段归位；仍只有一个「保存设置」按钮，一次 PUT 全部键。
- env 返回 JWT_SECRET set=false 时显内联警示、set=true 时不显。
- 既有断言（字段可见、敏感项掩码）保持绿。
- 手动复验（待真机）：浏览器实测增删行手感、保存往返、JWT_SECRET 警示展示，需用户确认。
