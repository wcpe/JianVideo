# 功能规格：v0.21.0 v2 文档与架构重构

> 状态：开发中　·　关联 PRD：FR2-001 / FR2-002 / FR2-003 / FR2-004　·　阶段：P0 `0.21.x`　·　分支：未指定

## 1. 背景与目标

当前 PRD 已废弃旧周任务式分期，但 v2 最新需求进一步把产品边界从“轻量家庭媒体中心”调整为“自托管视频素材与 AI 媒体中心”。因此 P0 需要重新冻结规格：视频优先、存储库优先、PixiJS 高密度渲染、Space 策略边界、AI 可替换、原文件安全、可信源分层和多端矩阵。

本规格定义 `v0.21.x` 的首批工作：文档归真、apps/packages 目标架构、P0.5 架构与工具链冻结门、PixiJS/Mockup/wiki UI 博物馆路线、数据库索引性能预算、旧能力矩阵和兼容迁移边界。`0.21.0` 是 P0 的起点；后续 `0.21.1`、`0.21.2` 等 patch 都仍属于 P0；P0.5 也归属 `0.21.x`，完成后再进入 P1 `0.22.x`。

## 2. 需求

- 重建 PRD：从 `0.21.0` 开始按产品路线组织，不再把周任务写进分期。
- 归档旧 PRD：旧的 `v0.20.x` 前功能长表保留为历史文档，便于查已交付能力。
- 新增路线图：以 `0.21.x` 作为 P0 规格冻结版本线，定义 P0-P7 RC 与 GA 的版本线规则。
- 确立目标架构：采用 `apps/*` + `packages/*`，并预留 Web、Desktop、Android、iOS、Android TV、安卓车机。
- 确立 P0.5 工具链：冻结 pnpm、Turborepo、Vite、React Router、TanStack Query、Zustand、react-i18next、MSW、PixiJS。
- 确立 wiki UI 博物馆：`apps/wiki` 展示全部 UI 控件、mockup、PixiJS 样例、HLS 预览卡、任务队列状态和代码片段。
- 确立静态检查门：Go、TypeScript、Rust、Kotlin、Swift 都按目标端最严档定义质量门。
- 确立 PixiJS 方向：首个 mock UI 就用 PixiJS 测试 100 万素材渲染，React DOM 壳层不进入核心滚动热区。
- 确立存储库优先：移除上传作为 1.0 主线要求，入库以存储库扫描和索引为主。
- 确立视频优先：HLS 预览、转码任务队列、任务监控和审核流优先于相册/照片娱乐能力。
- 确立 Space 边界：权限、删除、同步、AI 可见性、分享、审计和写回都按 Space 执行。
- 确立 AI 原则：模型、索引、推理节点和重建策略可替换、可审计。
- 明确性能验收：P0 定义 100 万前端渲染和 500 万到 1000 万后端索引预算；P1/P2 实现可运行 Benchmark。

范围外：

- 本规格不直接移动业务代码。
- 本规格不直接引入新依赖；PixiJS 等依赖在后续实现 spec 中单独确认。
- 本规格不直接改数据库 schema；索引和 schema 调整在 P2 对应 spec 中实现。

## 3. 设计

目标目录结构由 [ADR-0054](../adr/0054-apps-workspace-toolchain-quality-gates.md) 取代 ADR-0052，并由 [ADR-0053](../adr/0053-video-ai-pixijs-space-baseline.md) 扩展产品和技术基线。

建议迁移顺序：

1. `apps/wiki`：UI 博物馆和 mockup 先行，承载 React 壳层组件、主题、任务状态组件、PixiJS 渲染样例和代码片段。
2. `packages/render-pixi`：PixiJS 渲染热区，承载媒体网格、时间轴、纹理池、可见窗口和交互层。
3. `packages/theme`：主题 token、密度、颜色、端能力适配。
4. `packages/ui`：非滚动热区组件，如按钮、筛选、面板、任务卡、审核控件、播放器控制条。
5. `packages/media-client`：统一 API 类型、Space 上下文、任务状态、权限上下文和端能力检测。
6. `packages/mock` 与 `packages/benchmark`：生成 100 万前端素材 mock、500 万/1000 万后端索引数据和前后端 Benchmark 报告。
7. `packages/eslint-config` 与 `packages/typescript-config`：共享 TypeScript/React 最严静态检查和 tsconfig。
8. `apps/mock-studio`：Mock 场景、百万素材数据集和交互脚本工作台。
9. `apps/web`：主 Web/PWA。
10. `apps/server`：Go 服务目录迁移，保持一体化部署和 go:embed 能力。
11. `apps/desktop`、`apps/android`、`apps/ios`、`apps/tv`、`apps/automotive`：后续复用 Web/API client/主题/权限模型。

## 5. 验收标准

- PRD 中的分期只描述阶段主题，不再包含几十条周任务式条目。
- v2 PRD 明确 `0.21.0` 开始的路线、FR2 编号和阶段验收。
- 路线图明确 `0.21.x` 属于 P0，patch 不设固定上限，阶段完成后进入下一条 minor 版本线。
- ADR-0052 已被 ADR-0054 取代；ADR-0053 明确视频优先、PixiJS、Space、AI 和可信源基线；ADR-0054 明确 apps/packages 工作区、前端栈、wiki UI 博物馆和静态检查门。
- P0 补齐旧能力矩阵、性能预算表和旧 specs 处理策略，避免 v2 路线继续被旧 FR 编号和临时 UI 修补污染。
- 当前代码行为不因本次文档重构改变。
- 后续任何非平凡功能都能从 PRD 的 FR2 编号路由到对应 spec。

## 6. 风险 / 待定

- PixiJS 是新依赖，实际引入前必须在 P1 实现规格中确认包、版本、渲染边界和测试方式。
- 1000 万资产与 10 到 50 用户可能超过当前 SQLite 索引能力，必须用 Benchmark 决定是否引入新索引/数据库方案。
- AI 模型、向量索引和推理节点会影响部署复杂度，必须保持可替换与可审计。
- apps/packages 迁移会触碰构建脚本、CI、go:embed 和前端测试路径，必须拆成小批次。
- 历史 `docs/specs/` 仍有大量旧 FR 编号规格，只能作为背景引用，不能作为 v2 排期依据。
