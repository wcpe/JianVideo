# 功能规格：前端关键浅测补强

> 状态：开发中　·　关联 PRD：FR-125　·　分支：claude/suspicious-snyder-718ae6

## 1. 背景与目标

前端 97 个测试文件中 53 个含用户交互（userEvent/fireEvent），44 个不含。但「不含交互」≠「浅测」——VideoPlayer.*（追播/自适应/缓冲）、路由守卫（ProtectedRoute/RequireAnon/RequireSetup）、useScanProgress 等是经 mock/状态驱动的**行为测试**，价值高、不应动。真正的「render-only 浅测」是只断言元素存在、未验证行为/条件渲染的少数表现层组件与页面测试。本 FR 对**这部分关键浅测**补行为/交互/条件渲染断言，提升测试有效性。属第十三期（P13），依赖 FR-123/124（已落地）。

## 2. 需求（要什么）
- 审计 44 个无交互测试，**逐一分类**：(a) 真·render-only 浅测（仅断言存在）；(b) 已是行为测试（状态/mock 驱动）——后者**不动**。
- 对 (a) 中**用户可见、有行为可验**的关键组件/页面：补实质断言——交互（点击/输入/提交）后的 DOM/回调/状态变化，或 prop 驱动的条件渲染差异（不同 props/状态渲染不同）。
- 避免镀金：纯展示、无分支无交互的琐碎组件不强行堆低价值断言（简单优先）。
- 范围内：`frontend/src/**/*.test.tsx` 测试文件本体。
- 不做（范围外）：改业务组件源码、覆盖率门禁（FR-126）、E2E（FR-127）。

## 3. 设计（怎么做）
- 逐个读 44 个候选测试 + 其被测组件，判定 (a)/(b)。
- 对 (a) 关键项补断言，优先级：用户可见页面与交互组件 > 表现层组件。典型补法：
  - 表现层组件（如 MetricCard/MediaCardOverlay/TrendChart）：断言不同 props/状态下的**条件渲染差异**（如有数据 vs 空、不同变体），而非仅「渲染了」。
  - 页面（如 OverviewPage）：断言关键数据/区块按 mock 数据正确呈现、空态/异常态差异。
  - 有交互能力却没测交互的：补 userEvent 交互 + 结果断言。
- 不改被测组件行为；仅增强测试。

## 5. 验收标准（AC-29）
- 选定的关键浅测均含实质行为/交互/条件渲染断言（非仅断言存在）。
- `npm test` 全绿；用例数较补强前**只增不减**（覆盖率因此不会下降，FR-126 量化）。
- `npm run lint` 0 告警、`npm run format:check` 干净。
- 报告列出 44 候选的分类与「补强了哪些、补了什么断言」，便于复核非镀金。

## 6. 风险 / 待定
- 主观性高：以「是否验证了行为/条件，而非仅存在」为补强判据；纯展示无分支组件不硬补。
- 覆盖率量化在 FR-126（本 FR 只保证只增不减用例与断言）。
- 个别「无交互但已行为驱动」的测试（VideoPlayer.* 等）明确**不动**，避免无谓改动高风险组件的测试。
