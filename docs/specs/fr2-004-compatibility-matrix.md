# 功能规格：v2 兼容迁移与旧能力矩阵

> 状态：开发中　·　关联 PRD：FR2-004　·　阶段：P0 `0.21.x`　·　分支：未指定

## 1. 背景与目标

v2 最新定位变为自托管视频素材与 AI 媒体中心。旧 PRD 已归档到 `docs/archive/PRD-v0.20-history.md`，其中很多能力仍有价值，但优先级必须按“视频优先、存储库优先、Space 优先、AI 可替换、原文件安全”重新归类。

处理方式：

- **保留**：能力继续作为 v2 契约，目录迁移和前端重做不能破坏。
- **重做**：能力目标保留，但 UI/架构/实现会在 v2 阶段重建。
- **推迟**：能力暂不进入 1.0 主线，保留为后续 backlog。
- **废弃**：旧路线或旧实现不再作为有效要求。

## 7. 迁移兼容合同

- 现有 SQLite 数据、配置、媒体库路径和历史媒体记录不得因为目录迁移丢失。
- `config.yml`、环境变量、运行期 settings、工具路径和代理设置必须有迁移说明。
- 公开 API 变更默认保持兼容；破坏性变更必须写迁移说明并延后到明确阶段。
- go:embed 单二进制发布能力必须保留；apps/packages 不能强迫用户部署多个服务。
- 源文件删除、迁移、写回、同步和分享匿名访问必须继续做路径范围校验，并补事件日志策略。
- 旧 `docs/specs/` 可以作为历史背景引用，但不能直接续写成 v2 工作项。
