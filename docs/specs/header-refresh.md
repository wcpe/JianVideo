# 功能规格：页眉刷新按钮（FR-114）

> 状态：开发中　·　关联 PRD：FR-114（扩 FR-67/FR-95）　·　分支：feature/fr-c-app-shell

## 1. 背景与目标
FR-67 仅给时间轴页加了页内刷新按钮。本 FR 在全局页眉新增一个刷新按钮，适用于任意路由页面：点击仅重载当前路由页面的内容数据，不整页 reload、不重载导航/页眉、不重置登录态。属 P11。

## 2. 需求（要什么）
- 页眉新增刷新按钮（`ActionIcon` + `IconRefresh`，带无障碍标签）。
- 点击仅重新拉取当前路由页面的内容数据。
- 不触发整页 `location.reload()`；导航栏 / 页眉不重载；登录态不被重置。
- 范围内：仅改 `AppLayout`（页眉加按钮 + 内容区刷新机制）。
- 不做（范围外）：移除 FR-67 时间轴页内刷新按钮（两者并存，互不影响）；为各页单独定制刷新逻辑。

## 3. 设计（怎么做）
- 无新 ADR（纯前端壳机制，不涉架构决策）。
- 机制：`AppLayout` 持 `refreshNonce` 状态，刷新按钮 `onClick` 自增。`AppShell.Main` 内主内容区包裹元素的 `key` 由 `${pathname}:${refreshNonce}` 组成——
  - 路径变化：RouteTransition 以路径为 key 触发淡入（FIX-2 后），同时内容重挂载；
  - 刷新序号变化：路径不变但 key 变化，内容区重挂载、重跑各页数据拉取副作用（如 `useInfiniteMedia`/`useEffect` 拉取），仅刷新内容数据。
- 选 key-remount 而非「刷新事件/上下文让各页订阅重拉」：最简、零侵入各页、对所有路由统一生效（各页本就在挂载时拉数据），符合简单优先。
- 导航栏 / 页眉位于 `AppShell.Main` 之外，不在该 key 作用域内，故不重载；登录态由 auth store / Cookie 持有，重挂载内容不触动。

## 4. 任务拆分
- [x] `AppLayout`：页眉加刷新 `ActionIcon`（`IconRefresh` + 无障碍标签）
- [x] `AppLayout`：`refreshNonce` 状态 + 内容区 key 叠加刷新序号
- [x] `AppLayout.test.tsx` 新增断言（刷新按钮存在、点击使内容区 key 变化致重挂载、导航/页眉不重载）
- [x] 文档同步：PRD 状态、spec、CHANGELOG

## 5. 验收标准
- 页眉存在刷新按钮（无障碍名「刷新当前页面」）。
- 点击后当前路由内容区重挂载（重跑数据拉取），导航栏 / 页眉不重载、登录态不被重置、不整页刷新。
- 既有 `AppLayout.test.tsx` 断言全绿（含 FIX-2/FR-54/61/83/85/74/95/115 回归）。
- `frontend/` 下 `npm run build`（tsc -b）+ vitest 全绿。
- 真机维度（桌面 + 窄屏）：点击刷新仅内容重拉、导航/页眉/登录态不变 — 标「待真机验」，由主控统一真机抽查。

## 6. 风险 / 待定
- 内容区重挂载会丢失页面内部本地态（如滚动位置、未提交筛选）——这正是「刷新」语义所期望，符合 FR-67 既有刷新行为。
