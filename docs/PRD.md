# 产品需求文档（PRD）：轻量级单用户视频媒体服务器

> 需求的单一真源（WHAT / WHY），也是产品的**需求登记册 + 路线图**——全生命周期都在记，不是一次性文档。每个需求在 §4 加一行 FR（带优先级/期 + 状态），交付即标版本；§4 FR 表是迭代中最常动的部分（🔥 高频），分期（§7）只是其中很小、很静的一页粗线条规划。单功能的详细规格放 `docs/specs/`，PRD 只保留"一行 FR + 期 + 状态"的索引级。

## 1. 背景与目标

构建一款轻量级、单用户的私有视频媒体服务器。后端采用 Go 语言开发，前端使用 React + TypeScript 构建，前端编译产物通过 `go:embed` 完全内嵌于 Go 二进制文件中，实现单文件无额外依赖的便捷部署。系统核心定位为"个人家庭影音中心"，聚焦于高兼容性播放、极致的硬件转码性能，以及 Web 端对动态 TS 流的完美追随播放。

### 非目标

- 不做多用户权限管理与认证体系（单用户模式）
- 不做移动端原生 App（PWA 或后续阶段考虑）
- 不做在线流媒体订阅或分享功能
- 不做分布式集群部署
- 不做实时弹幕、评论等社交功能

## 2. 角色

- **家庭用户**：通过 Web 界面浏览、播放本地或 NAS 上的视频资源，无需关心底层格式差异。

## 3. 用户故事

- 作为家庭用户，我希望将多个硬盘/目录的视频和图片统一汇聚到一个媒体库中，以便集中浏览和管理。
- 作为家庭用户，我希望直接添加 SMB 网络共享路径作为媒体库源，以便播放 NAS 上的视频而无需手动挂载。
- 作为家庭用户，我希望新增媒体文件后媒体库自动更新，以便省去手动扫描的等待。
- 作为家庭用户，我希望能为单个媒体库目录追加自定义图片/视频后缀，以便索引特殊格式且不影响其他目录。
- 作为家庭用户，我希望所有视频格式都能直接播放，以便不用关心文件格式差异。
- 作为家庭用户，我希望在网络波动时视频自动切换码率不卡顿，以便获得流畅的观看体验。
- 作为家庭用户，我希望拖动进度条后画面立即响应，以便快速定位想看的内容。
- 作为家庭用户，我希望在转码进行中就能开始边下边播，以便不用等整个文件转完。
- 作为家庭用户，我希望通过硬件加速降低转码 CPU 负载，以便在低配设备上也能流畅转码。

## 5. 非功能需求（NFR）

- **NFR-01 转码性能**：硬件加速开启时，1080p H.264→H.265 转码帧率不低于源视频帧率的 90%。
- **NFR-02 首帧延迟**：Seek 后首帧画面出现时间不超过 2 秒（依赖 GOP 对齐与 I 帧命中）。
- **NFR-03 追播延迟**：边下边播模式下，播放器末端与文件写入末端的延迟控制在 3-5 秒内。
- **NFR-04 内存占用**：单个转码任务的内存占用不超过 512MB。
- **NFR-05 并发能力**：支持至少 3 个并发转码流（硬件加速受硬件能力限制时可降级）。
- **NFR-06 跨平台**：最终交付物为单个可执行文件，支持 Windows/Linux/macOS。
- **NFR-07 无外部依赖**：运行时无需预装 FFmpeg、Node.js 等外部依赖，所有配置通过配置文件或环境变量控制。
- **NFR-08 媒体库规模**：支持不低于 10,000 个视频文件的元数据管理，目录浏览响应时间不超过 500ms。

## 6. 验收标准

- **AC-01**：添加本地目录后，递归扫描可将目录内所有内置图片/视频文件在 30 秒内出现在媒体库中（需用户确认）。
- **AC-02**：删除或移动文件后，媒体库在 10 秒内自动更新（需用户确认）。
- **AC-03**：H.264+AAC 的 MP4 文件在浏览器中直接播放，不触发转码（需用户确认）。
- **AC-04**：H.265/MKV 等非浏览器兼容格式自动触发转码，3 秒内开始播放（需用户确认）。
- **AC-05**：拖动进度条后 2 秒内画面更新（需用户确认）。
- **AC-06**：转码进行中即可开始播放，无需等待转码完成（需用户确认）。
- **AC-07**：硬件加速转码时 CPU 占用率低于软件转码的 50%（需用户确认）。
- **AC-08**：最终交付为单个可执行文件，在 Windows/Linux/macOS 上均可运行（需用户确认）。
- **AC-09**：登录后刷新页面，认证状态保持，右上角仍显示用户名（需用户确认）。
- **AC-10**：手机端（< 768px）侧边栏默认折叠，点击汉堡菜单按钮可展开/收起（需用户确认）。
- **AC-11**：自定义后缀绑定到单个媒体库目录，删除目录时关联自定义后缀一并清理，其他目录不受影响。
- **AC-12**：Windows 路径下文件目录视图可正常列出子目录和文件，面包屑不出现 `/D:` 这类错误路径。
- **AC-13**：根路由 `/` 默认按添加时间倒序展示媒体（时间轴视图，FR-A 已将时间轴定为首页，原 `/timeline` 入口并入 `/`），图片点击打开预览，视频点击进入播放页。
- **AC-14**（FR-21）：`/system` 页加载后展示当前系统信息（OS/架构/CPU 数/主机名/Go 版本/应用版本）与 ffmpeg 可用性及版本；点击「测试编解码器」后展示各候选编码器的「是否编入当前 ffmpeg / 试编码是否成功」，「复制结果」可将纯文本报告写入剪贴板。
- **AC-15**（FR-21，需用户确认）：在装有 Intel/NVIDIA 的机器上运行打包产物，`/system` 页对相应硬件编码器（如 `h264_qsv`/`h264_nvenc`）报告试编码成功。
- **AC-16**（FR-22，需用户确认）：`make package` 在 Windows 与 Linux 各自产出单二进制发布包，随包 ffmpeg/ffprobe 被启动时自动发现，无需手动配置即可运行与播放。

## 7. 分期（路线）

各期只描述**主题 / 目标**；**具体哪个 FR 属于哪期，以 §4 FR 表的优先级 / 期列为唯一来源**——加需求即在表里标期，本节不重复列编号、不随 FR 增长而改。

- **第一期（MVP）**：核心媒体库 + 全格式转码播放 + 基础 Web 界面。实现多目录聚合、实时路径监控、FFmpeg 流式转码、HLS/TS 输出、mpegts.js 播放内核、边下边播追播机制、精准 Seek、硬件加速（Intel QSV + NVIDIA NVENC）、单用户认证、时间轴视图。
- **第二**期：SMB 网络共享支持 + 自适应码率（ABR）+ 文件目录视图 + 双进度条 + 字幕支持增强。
- **第三**期**：性能优化 + 更大规模媒体库支持 + 可选 PWA + 运维工具完善。
- **第四期（发布与分发工程）**：Go 模块社区化（`github.com/wcpe/JianVideo`）、GitHub Actions 多平台原生构建与自动发布（正式 release 按版本号打 tag + 普通 push 发 prerelease）、服务器端二进制自更新（拉取 GitHub release、校验 checksum、替换、自动重启、回滚）。
- **第五期（高级编码与自适应播放）**：硬件加速检测统一为实测真源 + 持久化缓存，补齐 AMD AMF 及全硬件家族（VAAPI/VideoToolbox/Vulkan）与 AV1/HEVC/VP9 探测；转码目标编码可配置；非 H.264 编码经 fMP4 + 浏览器原生 MSE 播放路径输出，按客户端能力自适应降级（H.264 维持 mpegts.js+TS 不变）。
- **第六期（界面与运维完善）**：可收缩左侧导航、系统信息与设置合并为 tab 化单页（参考宝塔）、环境变量查看与 ffmpeg 路径配置/检测、页脚版本与开源协议页、页眉更新提示，以及自更新体验修复（TTL 缓存 / 放宽超时 / 网络失败优雅降级 / release notes markdown 渲染）。
- **第七期（界面交互与管理完善 + 创新储备）**：系统诊断页拆子 tab 与运行环境补齐、版本与开源协议入口移入导航、应用更新交互完善（缓存优先 / 强制刷新 / 模态框确认）、运行期配置设置页热更新、存储库后缀列管与卡片网格、目录浏览多库聚合、时间轴刷新与拖动预览、列表多选与右键批量删除（FR-59~69）；并登记一批创新储备（感知哈希去重、离线聚类相册、那年今日回忆、媒体健康巡检、命令面板、观看统计、GPS 轨迹、转码预设队列、分享增强、外部播放器深链，FR-70~79，按需逐项启动）。同时修复亮色模式黑底（硬编码深色 token）与时间轴缩放，归真 FR-32 拖动、收窄 FR-58 跳转范围。
- **第八期（界面体验打磨与可用性增强）**：基于真机走查的体验优化批次——缩略图透明托底/比例自适应/骨架占位/多尺寸响应式、登录页与品牌打磨、左导航分组、主题切换过渡与 `dimmed` 对比度达标、播放页操作收纳与影院模式、移动端筛选折叠、设置页结构化编辑与分区、空态体验统一、代理连通性测试、自更新下载进度与重试、批量操作扩展（加相册/打标签/打包下载）（FR-81~91）。
- **第九期（界面设计系统与播放/图片体验）**：基于两轮设计走查（200+ 点）的体验大改——先落设计系统地基（token / 色板 / 组件规范），再做应用框架 / 动效 / 无障碍 / 空态统一、媒体卡与各浏览页重设计，以及播放（直接播放 / 全屏沉浸 / 播放器控件）与图片（灯箱交互 / 查看器 UI / 统一媒体查看器框架）体验。严格地基优先：FR-92~94 串行先落，再分波推进 FR-95~107（FR-92~107）。

> **分期不会堆到上百**：期是粗粒度路线图横轴，数量很少（走到成熟通常 3~6 个），一期含很多 FR、跨很多版本。**产品成熟（1.0 后稳态迭代）就不再加"第 N 期"**，改按版本（CHANGELOG / tag）+ 功能（FR 表 / specs）组织。

## 8. 术语表

| 术语 | 含义 |
|---|---|
| HLS | HTTP Live Streaming，Apple 提出的基于 HTTP 的流媒体协议，使用 m3u8 索引 + ts 切片 |
| TS / MPEG-TS | MPEG Transport Stream，传输流容器格式，用于 HLS 切片 |
| MSE | Media Source Extensions，浏览器提供的 JavaScript API，允许 JavaScript 向媒体元素注入媒体数据 |
| FFmpeg | 开源多媒体处理框架，用于视频解码、编码、转码、流媒体处理 |
| QSV | Intel Quick Sync Video，Intel 核显硬件加速编解码技术 |
| NVENC / NVDEC | NVIDIA GPU 硬件加速编解码技术 |
| VAAPI | Video Acceleration API，Linux 视频硬件加速接口 |
| ABR | Adaptive Bitrate Streaming，自适应码率流媒体，根据网络带宽动态切换码率 |
| GOP | Group of Pictures，视频编码中两个关键帧之间的帧组，影响 Seek 精度 |
| I 帧 | 帧内编码帧（关键帧），可独立解码，Seek 对齐的基准点 |
| SMB / CIFS | Server Message Block / Common Internet File System，Windows 网络文件共享协议 |
| fsnotify / inotify | Linux 文件系统事件监听机制（fsnotify 是 Go 的跨平台封装） |
| go:embed | Go 1.16+ 提供的将静态文件内嵌到二进制文件的指令 |
| WAL | Write-Ahead Logging，SQLite 的预写日志模式，提升并发读写性能 |
| mpegts.js | 支持 MPEG2-TS 实时流播放的 JavaScript 库，基于 MSE API |
