# 范围纪律（防范围漂移 / 镀金）

> 依据 `docs/PRD.md` 与 `docs/ROADMAP.md` 的 v2 分期。**只做当前版本线该做的，不提前做、不顺手做。**

## 1. 当前阶段

当前已完成 P0–P4 的实现与验收；**P4：高密度媒体浏览器** 七项 FR 已随 `v0.25.0` 正式发布收口。后续开发范围进入 **P5：Space、安全与多用户** 的 `0.26.x` 版本线。P3 播放体验九项 FR 仍以 `v0.24.0-rc.1` 候选发布状态登记，正式 `v0.24.0` 另按该阶段收口流程处理。

## 2. P0 只做

- 废弃旧 PRD 分期，把旧长表归档为历史查询。
- 建立 v2 PRD、路线图、ADR 与规格入口。
- 明确自托管、视频优先、Space、AI 可替换、可信源、PixiJS 和索引性能预算。
- 明确旧能力矩阵，废弃旧周任务式分期。
- 为后续代码迁移写规格，不在没有规格和验收的情况下直接搬业务代码。

## 2.1 P0.5 只做

- 冻结 `apps/*` + `packages/*` 目标架构。
- 冻结前端栈：pnpm、Turborepo、Vite、React Router、TanStack Query、Zustand、react-i18next、MSW、PixiJS。
- 冻结 `apps/wiki` UI 博物馆、mock 先行和 `packages/ui` 共享组件边界。
- 冻结 Go、TypeScript、Rust、Kotlin、Swift 的最严静态检查门。
- 为后续实际目录迁移、依赖引入和质量门落地写规格，不直接搬代码。

## 3. P0 严禁提前做

- 不直接迁移 `frontend/`、Go 服务或构建脚本，除非已有对应 spec 并获得确认。
- 不直接引入 pnpm workspace、Turbo、PixiJS、TanStack Query、Zustand、react-i18next、MSW 或端侧工具链，除非已有对应 spec 并获得确认。
- 不继续在旧时间轴页面上做大面积 UI 修补来替代 v2 规格。
- 不把周任务、真机反馈、临时修补项写进 PRD 分期。
- 不为 P1+ 能力预留无用空壳、占位接口或未验证抽象。

## 4. 后续阶段边界

- P0.5 `0.21.x`：架构与工具链冻结门。
- P1 `0.22.x`：Mockup、UI 博物馆与 PixiJS 原型实现。
- P2 `0.23.x`：存储库、索引与转码队列。
- P3 `0.24.x`：播放体验（王牌）。
- P4 `0.25.x`：高密度媒体浏览器。
- P5 `0.26.x`：Space、安全与多用户。
- P6 `0.27.x`：AI 索引、搜索与审核。
- P7 `0.28.x`：多端与交付质量门。
- P8 RC `0.29.x`：1.0 候选，只接受阻断修复、兼容修复、数据安全修复、性能回归修复、文档与验收补强。
- GA `1.0.0`：首个稳定版，进入严格 SemVer。

## 5. 越界先问

- 若某任务看起来需要后续阶段能力才能完成，停止并向用户确认，不自行扩大范围。
- 简洁方案优先：实现远多于必要（如 200 行 vs 50 行）时重写。资深工程师会觉得过度复杂的，就是过度。
